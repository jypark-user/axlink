## 1. 관리 방법

- 결함은 GitHub 이슈(라벨 `유형: 결함`)로 등록하고, 이 대장에 DEF 번호를 매겨 옮긴다. 번호는 등록 순서대로, 재사용하지 않는다.
- 검증 사이클에서 찾은 결함은 검증기록에 `DEF-V###` 로 먼저 남는다. 제품 결함으로 확정되면 이 대장에 DEF 번호를 매기고 `검증기록` 열에 그 번호를 적는다. 검증 중 찾아 같은 묶음 PR 로 바로 고친 결함은 GitHub 이슈 없이 검증기록 번호만 있다(이슈 열 `—`).
- 고친 PR 은 커밋 메시지에 요구사항 코드와 `Refs: GH-n` 을 단다. 대장의 조치 열은 그 PR 이다.
- 재시험은 관련 시험(IM-005 의 TST) 절차로 한다. 재시험을 통과해야 `종결`이다. 조치 PR 병합만으로는 `조치 완료`까지다.
- 이미지 취약점처럼 요구사항 하나에 걸리지 않는 결함은 요구사항 열을 비우고 운영 점검 항목으로 본다.

| 심각도 | 기준 |
|---|---|
| 높음 | 서비스가 멈추거나 데이터가 틀리게 들어간다. 보안 취약점 HIGH 이상 |
| 중간 | 기능 하나가 기대와 다르게 동작한다. 우회할 수 있다 |
| 낮음 | 표시·문구가 틀리다. 판단을 그르치지는 않는다 |
