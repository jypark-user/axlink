### 시작 조건과 통과 기준

- 5174 API 가 #248 의 GitHub 이미지로 떠 있고 health 의 version 이 그 커밋이다.
- 재생 원격 실행은 5174 서버 안 시험 DB `axlink_test` 에서 한다. 5174 데이터 DB 는 쓰지 않는다.
- 실연동은 시험 전용 사업을 따로 만들어 한다. 기존 시험 사업·인계용 사업과 섞지 않는다.
- 통과 기준은 IM-007 의 각 시나리오 기대값 그대로다. 낮추지 않는다.

### 실연동 절차 (차단이 풀리면 이 순서로)

1. 시험 원천을 고정한다. GitHub 시험 저장소의 커밋·이슈 목록, Redmine 시험 프로젝트의 이슈·버전을 수집 전에
   API 로 떠서 증거로 남긴다(원천 무기록 대조의 「전」).
2. 연결 등록과 연결 테스트(UC-010-S01·S02). REST 비활성은 Redmine 관리자가 REST 를 끈 상태에서 먼저 본 뒤 켠다.
3. 첫 수집(UC-011-S01·S11·S12): 건수·필드를 원천 목록과 대조한다.
4. 시험자료 준비용 원천 변경: 사용자 또는 허락받은 계정이 이슈 하나 닫기, 커밋 하나, Redmine 이슈 상태 하나
   바꾸기. 이 변경은 시험 준비 작업으로 따로 적는다(제품 커넥터는 읽기만 한다).
5. 증분 수집(UC-011-S03): 바뀐 것만 반영됐는지, 기준 시각이 전진했는지.
6. 확인 요청·조치 보고 뒤 원천 목록을 다시 떠서 1번과 비교한다(UC-050-S05·UC-051-S05, CC-01).
7. 권한 결손: 일부 종류 권한을 뺀 토큰으로 연결 테스트·수집(부분 성공 또는 실패 사유).
8. 실행마다 `record-junit --mode live --proves api,live-tool`(브라우저 확인을 함께 했으면 browser 도)로 남기고,
   화면 확인은 캡처 경로를 증거로 붙인다.
