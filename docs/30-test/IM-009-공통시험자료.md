## 0. 원칙

- 자료는 **작고 손으로 검산할 수 있는 크기**로 둔다. 건수가 다섯을 넘는 묶음은 표로 전부 적는다.
- 기대값은 **자료에서 손으로 계산**한다(7절). 계산식은 IM-001·진척률-산정체계의 정의를 따른다. 식이 정해지지 않은 지표는 7.7 절에 「DEC-nn 제안 (a) 예시」로만 적는다.
- 반올림은 **최종 표시 값에서만** 소수 첫째 자리 반올림(반올림 전 중간값은 소수 넷째 자리까지 보존). 7절 표에는 중간값(소수 넷째)과 표시값을 함께 적는다.
- 거절·실패 시나리오용 자료(잘못된 파일·중복·권한 없음)는 **시험 사업**(TD-PRJ-9)에 둔다. 검증·인계용 자료와 섞지 않는다(2026-10-29 추진 방향 3절).
- ID 접두·라벨 이름·파일 경로는 **이 시험 자료의 값**이지 제품의 보편 규칙이 아니다.
- **상태**는 6절에 이름을 붙여 고정한다. 시나리오는 시작 상태를 적고, 상태를 바꾸는 시나리오는 끝 상태를 적는다. 독립 실행이 필요하면 투입 스크립트로 그 상태를 복원한다.
- 「시험 DB 를 비운다」는 절차는 **폐기 가능한 전용 시험 DB** 에만 쓴다. 5174 의 검증·인계용 사업 데이터를 초기화하는 절차로 쓰지 않는다.

## 7. 기대값 (독립 계산)

중간값은 소수 넷째 자리, 표시값은 소수 첫째 자리(반올림). 비율은 % 로 적는다. 표시값은 반올림 전 원래 값에서 바로 구한다. 넷째 자리 중간값을 다시 반올림하지 않는다(예: T0 계획선 0.669461 → 중간값 0.6695, 표시값 66.9%. 0.6695 를 다시 반올림한 67.0% 가 아니다. DEF-V001).

## 8. 시험 환경과 재현 방법

| 항목 | 내용 |
|---|---|
| 자료 투입 | **폐기 가능한 전용 시험 DB** 를 비우고 1~5절을 투입해 상태 S0 를 만든다. 다른 상태(S0r·S0a·S1·S1r)는 6절의 「만드는 방법」 순서로 만든다. 5174·5173 의 사업 데이터는 이 절차의 대상이 아니다 |
| 자료·스크립트 관리 | 가상 파일(TD-DOC-*)과 투입 스크립트는 `tests/fixtures/` 에 두고 버전 관리한다. 비밀값(토큰·비밀번호)만 환경 변수. 이번 판에서는 작성·실행하지 않았다 |
| 기준일 | 집계·판정 시험은 기준일 매개변수(`at`)나 시험용 시계 주입으로 T0 를 준다. **공유 PC 시스템 시계를 바꾸지 않는다.** 주입 수단이 없는 화면 시험은 격리 환경(컨테이너 시계)에서 하고 그 사실을 결과에 적는다 |
| 외부 도구 | 실연동 시험은 시험용 GitHub 저장소·Redmine 프로젝트에 5.3~5.5 자료를 만든다(토큰 3종 포함). 그 외는 기록·재생 자료 |
| 모델 | 실모델 시험은 온프레미스 모델로 7.5 를 돌린다. 가짜 모델 시험은 분류·검색·검문 논리만 확인한다 |
| 시나리오 순서 | 각 시나리오는 시작 상태를 명시한다. 상태를 바꾸는 시나리오(UC-050-S01, UC-031-S01, UC-011-S03, UC-051-S01 등)는 끝 상태를 적고, 뒤 시나리오는 그 상태 이름으로 시작한다. 독립 실행하려면 투입 스크립트로 시작 상태를 복원한다 |
| 결과 기록 | IM-005 에 환경·버전·기준일·실제/모의·판정자를 적는다 |
