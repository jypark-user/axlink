발주 (재)전주정보문화산업진흥원 · 수행 유저인사이트(주)
**v0.2.2 초안** · 2026-11-05 · 검토용

> 불일치 목록으로 남겼고, 이번에 화면을 바꾸지는 않았다.

## 0. 읽는 법

용어마다 아래 항목을 적는다. 비어 있는 항목은 "—" 다.

| 항목 | 뜻 |
|---|---|
| ID | `GL-###`. 이름이 바뀌어도 번호는 유지한다 |
| 정의 | 이 사업에서의 뜻 |
| 쉬운 설명·예 | 처음 보는 사람을 위한 말과 예 |
| 유사어·이전 명칭 | 같은 뜻으로 쓰였거나 헷갈리는 말 |
| 문맥·관련 문서 | 어디서 쓰는지와 근거 문서 |
| 화면 표현 | 사용자 화면에서 쓰는(써야 하는) 말. 지금 화면과 다르면 7절에 적는다 |
| 매뉴얼 | 사용자 매뉴얼에 넣는지(○ 사용자 용어 · △ 설명만 · × 내부 용어) |
| 내부 대응 | 코드·DB·영문 용어 |

### GL-014 요구사항 등록·확정 / 확정본 (내부: 기준선)

| 항목 | 내용 |
|---|---|
| 정의 | 명세서에서 뽑은 **확정 전 요구사항 목록**을 용역사가 정리·제출하고 발주기관이 확정하는 절차와, 확정된 결과(**확정본 v1**). 확정은 "이 사업의 요구사항은 이것이다"를 정하는 것이며 구현·검증·인수가 아니다 |
| 쉬운 설명·예 | 용역사가 올린 41건을 발주기관이 확정하면 요구사항 화면·이행률·추적표·AI 답이 그 41건을 기준으로 삼는다 |
| 유사어·이전 명칭 | **기준선**(설계·코드·API 이름), baseline, 요구사항 베이스라인 |
| 문맥·관련 문서 | 협의 1-1절 · ARC-028 · UC-020·UC-021 · 2026-10-29 추진 방향(매뉴얼은 '기준선' 대신 화면 표현을 따른다) |
| 화면 표현 | **요구사항 등록·확정**(화면·버튼), **확정된 요구사항 목록 · 확정본 v1**(띠), 상태 **용역사 정리 중 / 발주기관 확정 대기 / 확정** |
| 매뉴얼 | ○ (사용자 용어로) · '기준선'은 × (내부 용어, 설계 문서에서만) |
| 내부 대응 | `requirement_baseline(status=DRAFT\|SUBMITTED\|CONFIRMED, version)`, `requirement_baseline_item`, URL `/p/{id}/requirement-baseline` |

### 7.1 구분이 필요한 묶음 (요약)

| 묶음 | 구분 | 참조 |
|---|---|---|

| 산출물 항목 / 지정 산출물 / 양식 / 문서 파일 / 제출본 / 파일 대조 판정 / 승인·반려 | 항목(22종 분류, 무엇으로 분류하나) · 지정 산출물(발주기관이 작업별로 「무엇을 내라」고 정한 것, 협의 범위) · 양식(어떻게 쓰나, 제출본이 아님) · 문서 파일(올린 것) · 제출본(초안 확정으로 항목에 등록한 한 버전 = 제출) · 파일 대조 판정(WBS 산출물 열과 파일을 대조한 관측, 제출본이 아님) · 승인·반려(버전에 대한 발주기관 판정) | GL-060~065·070 |

| 출처 / 근거 / 추적관계 / 미해결 참조 / 끊김·정정 | 출처는 AI 답의 조각, 근거는 추적관계가 생긴 원문, 추적관계는 연결 자체, 미해결 참조는 목록에 없는 ID, 끊김·정정은 연결의 상태 | GL-015·020~023 |
| 원천 도구의 상태 / AX Link 의 판정 상태 | 이슈 열림·닫힘, Redmine 상태, WBS 실적은 **원천 상태**. 근거 상태·발주기관 지정·제출 판정·승인·완료 확인은 **AX Link 판정** | GL-016·061·065·045 |
