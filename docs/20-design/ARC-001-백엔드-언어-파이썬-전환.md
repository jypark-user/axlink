## 1. 결정

**백엔드 구현 언어를 Java/Spring Boot 에서 Python 으로 전환한다.**

인수한 파일럿 `ax-link-ui-base` 의 백엔드 Java 코드 354파일은 실행 코드로 재사용하지 않는다.
**저장소에서 제거**하되(2026-08-28 개정, 5절), 참조본을 저장소 밖에 색인과 함께 남긴다.
프런트엔드·DB 스키마·설계 계약 문서는 그대로 승계한다(5절).

종전 스택 결정(Spring Boot + JdbcClient · React/Vite 단일 저장소)을 **교체**한다.

---

## 2. 배경

파일럿에서 인수한 백엔드는 Java/Spring Boot 였다. 이 사업은 임베딩·청킹·검색·비정형
문서 추출이 구현 비중의 상당 부분을 차지한다. 해당 계층의 생태계가 파이썬에 두터워
구현 언어를 재검토했다.

---

## 3. 기술 근거

### 3.1 AI·문서처리 생태계

임베딩·청킹·검색·문서추출 라이브러리가 파이썬에 두텁다. 파일럿은
`ai/port/LlmPort`·`EmbeddingPort` + `document/extract/TextExtractor` 로 포트가
분리되어 있어 사이드카 어댑터로도 같은 목적을 달성할 수 있으나(4절 대안 B),
계층 경계가 언어 경계와 겹치지 않아 유지 비용이 계속 발생한다.

### 3.2 HWP·HWPX 처리: 라이브러리 선정

2026-08-27 조사 결과.

| | `pyhwp` | `hwp-hwpx-parser` | (파일럿) `hwplib`+`hwpxlib` |
|---|---|---|---|
| 라이선스 | **AGPLv3+** | Apache-2.0 | Apache-2.0 |
| 최신 릴리스 | **2020-05-30** | 2026-01-29 (v1.0.0) | 안정 |
| Python 지원 | 2.7 기반, 3.9+ 빌드 문제 | 3.8 ~ 3.14 | 없음 (JVM) |
| **표 셀 구조** | **추출 불가 (평면 텍스트)** | 표·각주·미주·메모 추출 | 추출 가능 |
| HWPX | 미지원 | 지원 | `hwpxlib` |

**`pyhwp` 는 채택 불가다.** 두 가지 결격 사유가 있다.

1. **AGPLv3+** 라이선스다. 네트워크 서비스로 제공해도 소스 공개 의무가 전염된다. 발주기관
   납품물의 라이선스 조건을 확정할 수 없게 만든다.
2. **표 셀 구조를 읽지 못한다.** HWP 포맷에서 표는 본문 텍스트와 별도의 확장 컨트롤
   레코드로 저장되는데 `pyhwp` 는 이를 처리하지 않는다. **관공서 산출물은 표가 본문이다.**
   `SWFR.CON.007`(비정형 문서 추출)과 후속 정형화가 성립하지 않는다.

**`hwp-hwpx-parser` 를 채택한다.** 순수 파이썬(JVM 불요), Apache-2.0, HWP5+HWPX,
표까지 읽는다. 다만 2026-01 에 v1.0.0 이 나온 신생 단일 개발자 라이브러리라
검증된 `hwplib` 대비 신뢰성 확인이 필요하다 → 조기 실측으로 관리한다.

> **실측 결과 (2026-08-28)**: HWPX 표 셀 추출·마크다운 렌더 통과.
> 제안요청서(HWP 5.0, 602KB) → 70,650자 · 표 105개 추출 확인.

### 3.3 온프레미스 추론은 언어와 무관하다

전환 검토 중 *"온프레미스로 가야 하므로 Ollama 는 논외"* 라는 의견이 있었으나
전제가 사실과 다르다.

- **Ollama 는 이미 온프레미스다.** `localhost:11434` 에서 로컬 프로세스로 돈다.
- 실제 위반은 런타임이 아니라 **모델 태그**다. `application.yml:30` 의
  `${OLLAMA_MODEL_CHAT:qwen3.5:cloud}` 에서 **`:cloud` 접미사**가 Ollama 를 클라우드
  프록시로 만든다. 이것이 `QUR.RAG.001` 위반의 실체다.
  **태그를 `qwen3` 로 바꾸면 그 자리에서 폐쇄망이다.**
- 추론 런타임(Ollama · vLLM · transformers)은 **앱과 HTTP 경계로 분리**된다.
  따라서 추론 런타임 선택은 **앱 구현 언어를 결정하지 않는다.**

**이 항목은 전환의 근거가 아니다.** 다만 전환 여부와 무관하게 `:cloud` 태그 제거는
그대로 필요하다.

## 4. 검토한 대안

| 대안 | 내용 | 비용 |
|---|---|---|
| A. 현행 유지 | Java 유지, `:cloud` 태그만 교체 | 0 |
| B. 파이썬 사이드카 | 포트 뒤(모델·문서추출)만 파이썬. Java 유지 | 약 1주 |
| C. `rag/` 계층 이전 | RAG 오케스트레이션까지 파이썬 | 약 3~4주 |
| **D. 전면 재작성** | 백엔드 전체 파이썬 | **전량** |

**D 를 채택한다.** B·C 는 언어 경계가 계층 경계와 어긋난 채로 남아, 이후 AI·문서처리
작업마다 두 런타임을 함께 다뤄야 한다.

### 4.1 수용한 대가

파일럿 Java 코드를 실행하지 않으므로 **백엔드는 전 계층이 신규 개발이다.**
프런트엔드·DB 스키마·UI 자산은 승계하므로 화면 계층은 영향받지 않는다.

## 5. 승계 자산 / 폐기 자산

### 승계: 언어에 종속되지 않는 것

파일럿 원본 문서는 납품 산출물이 아니므로 저장소에 포함하지 않는다.
아래 경로는 파일럿 문서 집합 기준이다.

| 자산 | 비고 |
|---|---|
| **DB 스키마 `V1~V19`** | 언어 중립. Flyway 로 그대로 실행 |
| **프런트엔드 전체** | React/Vite. 빌드 통과 확인됨. **영향 없음** |
| `design/02-logical-api.md` | API 계약 (언어 중립) |
| `design/02-logical-datamodel.md` | 데이터 모델·enum·불변식 |
| `design/01-conceptual-domain.md` | 도메인 모델 |
| 위젯 템플릿 23종 · 인포 템플릿 · 시맨틱 카탈로그 정의 | 데이터(`spec_json`)이지 코드가 아니다 |
| 절대 규칙 1~9 | 전환과 무관하게 유지 |
| 요구사항 41건 · 추적성 ID 체계 · Git 규약 | 영향 없음 |

### 폐기: 저장소 밖 참조본으로 이관

> **개정 (2026-08-28)**: 최초 안은 `backend/` 를 저장소 안에 참조 구현으로 남기는
> 것이었다. **저장소에서 완전히 제거**하고 참조본을 깃 밖에 따로 두는 것으로 바꿨다.
> 저장소가 곧 시연 데이터라, 실행하지 않는 354파일이 커밋 이력·진척 산정·코드 검색을
> 계속 오염시키는 비용이 저장소 안에 두는 편의보다 크다는 판단이다.

| 자산 | 처리 |
|---|---|
| `backend/` Java 354파일 | **저장소에서 삭제.** 참조본은 저장소 밖에 색인과 함께 보관한다. 파이썬 구현이 해당 계층을 대체·검증하면 참조본에서도 지운다 |
| `backend/build.gradle` · Gradle 래퍼 | 위와 함께 이관 |
| `03-physical-backend.md` | 파이썬판 물리설계로 대체 작성 필요 (파일럿 원본은 별도 보관) |

> **참조본을 잃지 않는 이유**: 354파일은 동작하는 설계 근거다. 파이썬으로 옮기는 동안
> "원래 어떻게 풀었는가" 를 확인할 자료라, 깃에서만 빼고 로컬에는 남긴다.

## 6. 목표 스택

파일럿의 설계 결정 중 **언어에 종속되지 않는 근거**는 그대로 승계한다.

| 계층 | 선택 | 근거 |
|---|---|---|
| 런타임 | **Python 3.12** | `hwp-hwpx-parser` 지원 범위 안, 생태계 안정 |
| 웹 프레임워크 | **FastAPI** | SPA + REST 조합. Django admin 불필요. OpenAPI 자동 생성이 `02-logical-api.md` 계약 유지에 유리 |
| ASGI 서버 | uvicorn | |
| **DB 접근** | **psycopg 3 + SQL 직접 작성. ORM 사용 안 함** | `03-physical-backend.md` C-1 의 근거가 언어와 무관하게 성립한다. 시맨틱 레이어는 SQL 조립이 본질이고, `vector(1024)`·`tsvector`·부분 유니크 `on conflict`·`pg_trgm` 은 네이티브 SQL 이 필요하다. **SQLAlchemy ORM 은 JPA 와 같은 이유로 금지** |
| 마이그레이션 | **Flyway 유지 (Docker 이미지로 실행)** | `V1~V19` 를 재작성하지 않고 그대로 살린다. 앱에 JVM 이 들어가지 않는다. "새 `V##__` 파일로만" 규칙도 그대로 유지 |
| 검증·직렬화 | Pydantic v2 | Java `record` + Jackson 대체. `02-logical-api.md` 타입 계약 유지 |
| 인증 | PyJWT + FastAPI 의존성 | Spring Security `JwtAuthenticationFilter` 대체. Bearer·STATELESS 유지 |
| 스케줄러 | APScheduler + DB 잡 테이블 | Spring `@Scheduled` 대체. 단일 인스턴스 전제 유지 |
| **HWP·HWPX** | **`hwp-hwpx-parser`** | 3.2절 참조. Apache-2.0, 표 추출 가능 |
| PDF / DOCX / XLSX | pypdf · python-docx · openpyxl | **Apache Tika 대체 필요.** Tika 는 Java 라서 포맷별 개별 선정 |
| LLM · 임베딩 | httpx → Ollama (초기) → vLLM (온프레미스 확정 시) | **포트/어댑터 구조는 승계.** `LlmPort`·`EmbeddingPort` 를 프로토콜로 옮긴다 |
| 테스트 | pytest | |
| 린트·포맷 | ruff | Spotless 대체 |

### 6.1 승계하는 설계 결정

- **포트/어댑터 분리**: `LlmPort`·`EmbeddingPort`·`ToolConnector`·`TextExtractor`
- **어댑터는 실제 구현 + Fake 2벌**로 두어 테스트가 외부 프로세스에 의존하지 않는다
- **CONSTANT_CASE 단일 enum 표기**, 서버·DB CHECK·프론트 3자 일치(INV-18)
- **UTC 고정, 로컬 시각 변환은 프론트 책임**
