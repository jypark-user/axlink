## 1. 결정

**백엔드 구현 언어를 Java/Spring Boot 에서 Python 으로 전환한다.**

인수한 파일럿 `ax-link-ui-base` 의 백엔드 Java 코드 354파일은 **참조 구현(reference
implementation)으로만 보존**하고 실행 코드로 재사용하지 않는다. 프런트엔드·DB 스키마·
설계 계약 문서는 그대로 승계한다(§7).

이 결정은 `CLAUDE.md` §1 *"저장소는 파일럿 `ax-link-ui-base`를 시드로 삼는다.
Spring Boot(JdbcClient) + React/Vite 단일 저장소다"* 를 **교체**한다.

---

## 2. 배경 — 왜 이 문서가 필요한가

2026-08-27 작업 재개 시점에 수행 책임자가 *"파이썬으로 초기에 계획했는데 진행 중에
변질된 것 같다"* 고 제기했다. 저장소 기록을 조회한 결과는 다음과 같다.

| 확인 항목 | 결과 |
|---|---|
| 파이썬 백엔드 커밋 이력 | **없음.** 커밋 5개 전부 조회 |
| 삭제된 `.py` · `requirements.txt` · `pyproject.toml` | **0건** |
| 첫 커밋 `851443d` | 파일럿 인수 시점부터 이미 Java |
| 설계 문서 | PRD §2.1 · `01-conceptual-architecture` · `03-physical-backend` 전부 Java 확정 |
| 저장소 내 파이썬 | 도구 스크립트 4개뿐 (추적표·이슈생성·진행대시보드·Ollama 연속작업) |

**즉 이 저장소 안에서 "변질"은 일어나지 않았다.** Java 는 파일럿 인수와 함께 처음부터
들어왔다. 초기 파이썬 계획은 저장소 밖(제안 단계)에 있었고 이 저장소에 반영된 적이 없다.

그러나 **초기 계획이 파이썬이었다는 사실 자체는 저장소가 반증할 수 없다.** 제안서·
과업지시서는 이 저장소에 없다. 따라서 이 전환은 "잘못된 것을 되돌리는" 것이 아니라
**새로 내리는 결정**이며, 그래서 근거와 대가를 이 문서에 남긴다.

> 이 저장소는 AX Link 의 1번 샘플 프로젝트다(`CLAUDE.md` §0). 기술스택이 이유 없이
> 바뀐 기록은 그 자체로 우리 커넥터가 수집할 **데이터 결함**이 된다.

## 3. 제기된 근거와 사실 확인

수행 책임자가 제시한 근거 4건을 각각 확인했다. **2건 성립, 1건 부분 성립, 1건 불성립.**

### 3.1 초기 계획 스택이 파이썬이었다 — 확인 불가(저장소 밖)

§2 참조. 저장소는 이를 확인도 반증도 못 한다. **결정권자의 진술을 근거로 채택한다.**

### 3.2 AI·RAG 계층을 파이썬으로 다루고 싶다 — 성립

임베딩·청킹·검색·문서처리 생태계가 파이썬에 두텁다. 다만 **이 근거만으로는 전면
전환이 도출되지 않는다.** 파일럿은 `ai/port/LlmPort`·`EmbeddingPort` +
`document/extract/TextExtractor` 로 이미 포트가 분리되어 있어, 파이썬 사이드카를
어댑터 한 벌로 꽂으면 호출부 수정 없이 같은 목적을 달성할 수 있다(비용 약 1주).

**전면 전환은 이 근거의 필요조건이 아니라 결정권자의 추가 선택이다.** 그 선택의
대가는 §5 에 기록한다.

### 3.3 HWP 처리 파이썬 라이브러리가 있다 — 성립, 단 리스크 이동

2026-08-27 조사 결과.

| | `pyhwp` | `hwp-hwpx-parser` | (현행) `hwplib`+`hwpxlib` |
|---|---|---|---|
| 라이선스 | **AGPLv3+** | Apache-2.0 | Apache-2.0 |
| 최신 릴리스 | **2020-05-30** | 2026-01-29 (v1.0.0) | 안정 |
| Python 지원 | 2.7 기반, 3.9+ 빌드 문제 | 3.8 ~ 3.14 | — (JVM) |
| **표 셀 구조** | **추출 불가 — 평면 텍스트** | 표·각주·미주·메모 추출 | 추출 가능 |
| HWPX | 미지원 | 지원 | `hwpxlib` |

**`pyhwp` 는 채택 불가다.** 두 가지 결격 사유가 있다.

1. **AGPLv3+** — 네트워크 서비스로 제공해도 소스 공개 의무가 전염된다. 발주기관
   납품물의 라이선스 조건을 확정할 수 없게 만든다.
2. **표 셀 구조를 읽지 못한다.** HWP 포맷에서 표는 본문 텍스트와 별도의 확장 컨트롤
   레코드로 저장되는데 `pyhwp` 는 이를 처리하지 않는다. **관공서 산출물은 표가 본문이다.**
   `SWFR.CON.007`(비정형 문서 추출)과 후속 정형화가 성립하지 않는다.

**`hwp-hwpx-parser` 는 채택 가능하다.** 순수 파이썬(JVM 불요), Apache-2.0, HWP5+HWPX,
표까지 읽는다. **다만 2026-01 에 v1.0.0 이 나온 7개월 된 단일 개발자 라이브러리다.**
검증된 `hwplib` 에서 신생 라이브러리로 **리스크가 이동**한다 → RSK-010.

### 3.4 온프레미스 추론이 필요하다 — 불성립(언어와 무관)

*"Ollama 는 논외인 게 온프레미스로 가야 해"* 라는 제기는 전제가 사실과 다르다.

- **Ollama 는 이미 온프레미스다.** `localhost:11434` 에서 로컬 프로세스로 돈다.
- 실제 위반은 런타임이 아니라 **모델 태그**다. `application.yml:30` 의
  `${OLLAMA_MODEL_CHAT:qwen3.5:cloud}` 에서 **`:cloud` 접미사**가 Ollama 를 클라우드
  프록시로 만든다. 이것이 파일럿 대조표의 유일한 「충돌」(`QUR.RAG.001`)이다.
  **태그를 `qwen3` 로 바꾸면 그 자리에서 폐쇄망이다.**
- 추론 런타임(Ollama · vLLM · transformers)은 **앱과 HTTP 경계로 분리**된다.
  따라서 추론 런타임 선택은 **앱 구현 언어를 결정하지 않는다.**

**이 근거는 전환을 지지하지 않는다.** 다만 전환 여부와 무관하게 `:cloud` 태그 제거와
GPU 확보(RSK-005)는 그대로 필요하다.

## 4. 검토한 대안

| 대안 | 내용 | 비용 | 판정 |
|---|---|---|---|
| A. 현행 유지 | Java 유지, `:cloud` 태그만 교체 | 0 | 기각 — 결정권자 반대 |
| B. 파이썬 사이드카 | 포트 뒤(모델·문서추출)만 파이썬. Java 유지 | 약 1주 | 기각 — 결정권자 반대 |
| C. `rag/` 계층 이전 | RAG 오케스트레이션까지 파이썬 | 약 3~4주 | 기각 — 결정권자 반대 |
| **D. 전면 재작성** | 백엔드 전체 파이썬 | **3개월 전량** | **채택** |

수행 책임자에게 A~D 의 비용을 제시하고 **D 를 선택**받았다. 대안 B 가 §3.2 의 목적을
1/12 비용으로 달성한다는 점은 제시되었고, 그럼에도 D 가 선택되었다.

## 5. 수용한 대가

**이 전환에는 되돌릴 수 없는 비용이 따른다. 아래를 인지하고 진행한다.**

### 5.1 파일럿 대조표 판정이 무효화된다

`docs/20-design/파일럿-대조표.md` 의 판정은 "파일럿 Java 코드에 대응 구현이 있는가"를
기준으로 매겨졌다. 그 코드를 쓰지 않으므로 판정의 근거가 사라진다.

| 판정 | 전환 전 | 전환 후 |
|---|---|---|
| 구현 (검증·보완) | **25건** | 0건 |
| 부분 (확장) | 7건 | 0건 |
| 없음 (신규 개발) | 7건 | **41건 전부** |
| 충돌 (교체) | 1건 | — (자연 해소) |

**요구사항 25건이 "확인하고 근거 남기면 닫히는 일"에서 "처음부터 만드는 일"로 바뀐다.**

### 5.2 일정 버퍼가 소멸한다

`작업계획.md` 는 *"RAG 파이프라인이 파일럿에서 이미 동작하므로 남은 일은 모델 전환과
폐쇄망 검증이고, 신규 개발이 아니다"* 를 근거로 **RSK-008(RAG·LLM 구간 버퍼 없음)을
「낮음」으로 낮췄다.** 그 근거가 사라진다 → **RSK-008 을 「높음」으로 되돌린다.**

W7~W9 구간의 해소되었던 버퍼도 함께 사라진다.

## 6. 목표 스택 (제안 — 이 PR 에서 확정)

파일럿의 설계 결정 중 **언어에 종속되지 않는 근거**는 그대로 승계한다.

| 계층 | 선택 | 근거 |
|---|---|---|
| 런타임 | **Python 3.12** | `hwp-hwpx-parser` 지원 범위 안, 생태계 안정 |
| 웹 프레임워크 | **FastAPI** | SPA + REST 조합. Django admin 불필요. OpenAPI 자동 생성이 `02-logical-api.md` 계약 유지에 유리 |
| ASGI 서버 | uvicorn | |
| **DB 접근** | **psycopg 3 + SQL 직접 작성. ORM 사용 안 함** | `03-physical-backend.md` C-1 의 근거가 언어와 무관하게 성립 — 시맨틱 레이어는 SQL 조립이 본질이고, `vector(1024)`·`tsvector`·부분 유니크 `on conflict`·`pg_trgm` 은 네이티브 SQL 이 필요하다. **SQLAlchemy ORM 은 JPA 와 같은 이유로 금지** |
| 마이그레이션 | **Flyway 유지 (Docker 이미지로 실행)** | `V1~V19` 를 재작성하지 않고 그대로 살린다. 앱에 JVM 이 들어가지 않는다. `CLAUDE.md` 의 "새 `V##__` 파일로만" 규칙도 그대로 유지 |
| 검증·직렬화 | Pydantic v2 | Java `record` + Jackson 대체. `02-logical-api.md` 타입 계약 유지 |
| 인증 | PyJWT + FastAPI 의존성 | Spring Security `JwtAuthenticationFilter` 대체. Bearer·STATELESS 유지 |
| 스케줄러 | APScheduler + DB 잡 테이블 | Spring `@Scheduled` 대체. 단일 인스턴스 전제 유지 |
| **HWP·HWPX** | **`hwp-hwpx-parser`** | §3.3. Apache-2.0, 표 추출 가능 → RSK-010 으로 관리 |
| PDF / DOCX / XLSX | pypdf · python-docx · openpyxl | **Apache Tika 대체 필요** — Tika 는 Java. 포맷별 개별 선정 → RSK-011 |
| LLM · 임베딩 | httpx → Ollama (초기) → vLLM (온프레미스 확정 시) | **포트/어댑터 구조는 승계.** `LlmPort`·`EmbeddingPort` 를 프로토콜로 옮긴다 |
| 테스트 | pytest | |
| 린트·포맷 | ruff | Spotless 대체 |

### 6.1 승계하는 설계 결정

- **포트/어댑터 분리** — `LlmPort`·`EmbeddingPort`·`ToolConnector`·`TextExtractor`
- **어댑터는 실제 구현 + Fake 2벌** — 테스트가 외부 프로세스에 의존하지 않는다
- **CONSTANT_CASE 단일 enum 표기** — 서버·DB CHECK·프론트 3자 일치(INV-18)
- **UTC 고정, 로컬 시각 변환은 프론트 책임**
