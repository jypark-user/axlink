# ARC-023 일반 이슈의 원천 마일스톤 표시 (최소안)

| | |
|---|---|
| 상태 | **초안** (구현 전 검토) |
| 일자 | 2026-10-08 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `SWFR.CON.003` `SWFR.WEB.001` `SWFR.PIP.007` `ARC-016` |

---

## 1. 문제

GitHub 마일스톤은 수집되지만(`raw_artifact` 의 `milestone`, 이슈 원본의 `milestone`) 표준 모델로
올라가지 않는다. 읽는 코드도 화면도 없다. 10-08 점검에서 GitHub 이슈 52건에 마일스톤이 지정돼 있는데
AX Link 일반 이슈 화면에서는 하나도 보이지 않았다. 발주기관은 "이 이슈가 어느 단계 목표인가" 를
도구에 들어가야만 안다.

## 2. 범위

**이번에 하는 것:** 일반 이슈 목록과 상세에 원천 마일스톤의 **이름·기한·상태**를 그대로 보인다.

**이번에 하지 않는 것 (구분):**

| 하지 않는 것 | 어디서 |
|---|---|
| 마일스톤 달성 기준 일정 준수율 계산 | `SWFR.PIP.007` 별도 작업 |
| 이슈를 WBS 항목에 자동 연결 | ARC-016 3단계(`issue.wbs_item_id`) |
| 마일스톤을 지표·차원으로 시맨틱 카탈로그에 넣기 | 필요해지면 별도 |
| 요구사항 이슈(요구사항 화면)에 표시 | 같은 표를 쓰면 쉽게 붙지만 이번 범위 밖 |

## 3. 설계

### 3-1. 저장

마일스톤 자체를 표로 둔다. 이슈에는 번호만 둔다. 이슈 원본 안의 마일스톤 사본은 이슈를 고칠 때만
갱신돼서, 마일스톤 기한이나 상태를 바꾸면 이슈 쪽 사본이 낡는다. GitHub 커넥터는 마일스톤 목록을
매 수집마다 통째로 받으므로(`github_connector.py`, `since` 를 쓰지 않는다) 마일스톤 표는 늘 최신이다.

```
milestone (V58)
  id, project_id, tool_connection_id, external_id(예: milestone:5),
  number, title, due_on(date, null 허용), state(OPEN|CLOSED), closed_at, source_url,
  source_updated_at, created_at, updated_at
  unique (tool_connection_id, external_id)

issue.milestone_id  uuid null  → milestone(id) on delete set null
```

- 승격(`app/standard/service.py`): 지금 `milestone` 은 원본만 남기고 건너뛴다. 이를 `milestone` 표
  upsert 로 바꾼다. 이슈 승격 때 원본의 `milestone.number` 로 같은 연결의 마일스톤을 찾아 잇는다.
- 원천에서 이슈의 마일스톤을 빼면 `milestone_id` 를 비운다. 마일스톤이 원천에서 지워지면 행은 남기고
  상태를 그대로 둔다(추적 근거 보존). 사라졌다는 표시는 이번 범위 밖.
- Redmine 의 `fixed_version` 도 같은 표로 올릴 수 있다(Version = 마일스톤, CLAUDE.md §2). 최소안은
  GitHub 먼저. Redmine 은 매핑 함수 하나를 더하면 된다.

### 3-2. API

`GET /api/projects/{id}/issues` 각 행과 상세에 아래를 더한다. 없으면 `null`.

```json
"milestone": { "title": "M4 통합 PoC 완성", "dueOn": "2026-10-23", "state": "OPEN", "url": "..." }
```

### 3-3. 화면

- 일반 이슈 목록에 "마일스톤" 열: `M4 통합 PoC 완성 · 10-23 · 진행 중`. 닫힌 마일스톤은 `완료`.
- 기한이 지났는데 마일스톤이 열려 있으면 기한을 강조만 한다. "지연" 판정·건수는 내지 않는다
  (그건 일정 준수율 작업의 몫이다).
- 마일스톤 없음은 빈칸 대신 `미지정`.
- 라벨은 발주기관 어휘로 쓴다(설계 제약 9). 상태 문구: 진행 중 / 완료.

## 4. 시험

- 승격: 원본 마일스톤 → 표, 이슈 원본 번호 → `milestone_id`. 마일스톤 기한 변경이 다음 수집 뒤
  이슈 화면에 반영된다. 이슈에서 마일스톤을 빼면 비워진다.
- API·화면: 지정·미지정·닫힌 마일스톤 세 경우.
- 5173 반영 전 5174 에서 자기 저장소 수집으로 52건 표시를 대조한다(GitHub 원천과 건수·이름 일치).

## 5. 대가

- 마이그레이션 하나(V58)와 승격 경로 변경. 기존 화면·지표 계산은 바뀌지 않는다.
- 이슈 목록 열이 하나 는다.

## 6. 구현 (11-02, GH-130)

설계 때 V51 로 적은 마이그레이션은 그 사이 번호가 차서 V58 로 넣었다. 나머지는 위 설계대로다.

- 승격은 원본을 종류 이름 순서로 읽어 이슈가 마일스톤보다 먼저 온다. 그래서 이슈마다 원본의
  마일스톤 번호를 모아 두고, 다 읽은 뒤 같은 연결의 마일스톤에 한 번에 잇는다.
- 마일스톤은 원본 보존(raw_only)이 아니라 승격 건수(`MILESTONE`)로 센다.
- 화면 기한 강조는 보는 사람의 오늘 날짜로 판단한다. 강조일 뿐이고 지연 건수로 세지 않는다.
- Redmine 버전(`fixed_version`)은 이번에도 올리지 않았다.
