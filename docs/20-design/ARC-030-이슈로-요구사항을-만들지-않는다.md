# ARC-030 이슈로 요구사항을 만들지 않는다

| | |
|---|---|
| 상태 | **확정** |
| 일자 | 2026-10-23 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `SWFR.PIP.002` `SWFR.PIP.003` `ARC-016` `ARC-025` `ARC-028`(2-3절의 연결 설정 끄기를 대체) |

---

## 1. 문제

요구사항 목록은 명세서(기준선)로 만든다(ARC-028). 그런데 기준선 기능 전에 만든 GitHub 연결은 "이슈로 요구사항 만들기"가 켜진 채 남았고, 그 사업이 기준선을 확정하기 전까지 요구사항 라벨(`유형: 요구사항`)이나 `[코드] 제목` 꼴의 이슈가 수집될 때마다 요구사항을 만들고 고쳤다. 5173 실제 사업(차세대 통합관제)이 그렇다.

같은 사업에 요구사항이 두 길로 생기면 목록이 무엇을 기준으로 한 것인지 설명할 수 없다. 화면과 설명서에도 "설정을 끈다", "도구 이슈에서 만든 요구사항" 같은 조건부 안내가 붙었다.

## 2. 결정

- 수집은 GitHub 이슈를 모두 **일반 이슈**로 올린다. 라벨·제목으로 요구사항을 가르지 않는다.
- 예전에 이슈로 만든 요구사항은 **지우지 않는다**. 그 이슈(출처 이슈)는 계속 그 요구사항의 열림·닫힘만 바꾼다. 정의(코드·제목·본문·중요도)는 바꾸지 않고, 발주기관이 지정한 상태가 있으면 지정이 이긴다(ARC-025).
- 명세서로 만든 요구사항과 ID 가 같은 이슈가 들어오면 일반 이슈가 되고, 적힌 ID 로 추적 링크가 이어진다. 요구사항의 출처가 되지 않는다.
- V56 이 남은 생성 설정을 모두 끈다. 코드는 `tool_connection.requirement_from_issues` 를 더 읽지 않는다. 이전 판으로 되돌릴 수 있게 열은 남긴다.
- 기준선 확정은 연결 설정을 건드리지 않는다. 확정 결과의 "끈 연결" 목록도 없앴다.
- 판별 이름 `requirementLabel` 은 예전 설정에 남아 있어 받기만 하고 쓰지 않는다. 거절하면 그 연결의 수집이 멈춘다.

## 3. 화면 말

| 전 | 후 |
|---|---|
| 원천 이슈 | 출처 이슈(명세서 전에 이슈로 만든 요구사항에만 있다) |
| 원천 이슈 닫힘 · 구현·검증 완료를 뜻하지 않음 | 출처 이슈 닫힘 · 구현 확인 아님 |
| 원천 연결 없음(문서·수기) | 출처 이슈 없음(명세서·직접 입력) |
| 요구사항으로 분류된 항목 제외 | 예전에 요구사항으로 만든 이슈 제외 |
| 지금 요구사항 n건은 도구 이슈에서 만든 것 | 지금 요구사항 n건은 기준선 밖에 있다 |

일반 이슈 지표의 산출 근거 문장도 V56 에서 같이 고쳤다.

## 4. 바뀌는 것

- 기준선을 확정하지 않은 사업은 새 요구사항 이슈가 생겨도 요구사항 목록이 늘지 않는다. 그 이슈는 일반 이슈 목록에 나온다.
- 5173 실제 사업의 요구사항 41건은 그대로다. 출처 이슈가 닫히면 지금처럼 "구현"이 된다.

## 5. 시험

| 확인 | 시험 |
|---|---|
| 요구사항 라벨·[코드] 제목 이슈도 일반 이슈가 된다 | `test_requirement_baseline.py::test_요구사항_라벨이_붙은_이슈도_…` |
| 명세서 요구사항과 같은 ID 의 이슈는 일반 이슈가 되고 추적 링크로 이어진다. 다시 수집해도 같다 | `…::test_명세서_요구사항과_같은_코드의_이슈는_…` |
| 예전에 이슈로 만든 요구사항은 출처 이슈의 열림·닫힘을 따르고 정의·지정은 그대로 | `…::test_확정_뒤_재수집은_…`, `test_requirement_decision.py` |
| 예전 설정의 `requirementLabel` 은 받고 저장하지 않는다 | `test_mapping_rules.py::test_예전_요구사항_라벨_키는_…` |

예전 데이터가 있는 사업은 시험에서 `tests/conftest.py` 의 `seed_issue_requirements` 로 흉내 낸다.
