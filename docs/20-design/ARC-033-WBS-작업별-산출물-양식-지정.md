## 1. 문제

「무엇을 내야 하나」는 용역사가 WBS 파일 산출물 열에 적은 자유 글뿐이었다. 발주기관이 작업마다 필요한 산출물을 정하거나 양식을 줄 자리가 없었다. 22종 인도 점검표는 유형별 현행 버전만 보여 작업과 잇지 못했다.

## 2. 결정

발주기관이 WBS 말단 작업마다 **지정 산출물 항목**을 둔다. 네 가지를 따로 관리한다.

| 구분 | 어디에 | 규칙 |
|---|---|---|
| 항목(무엇을 내나) | `wbs_designated_deliverable` (V66) | 이름(필수)·설명·분류(22종 중 선택)·작성 안내. 작업 하나에 여러 항목 |
| 양식(어떻게 쓰나) | 같은 표의 `template_*` 칸 | 문서 표에 넣지 않는다. 그래서 판정·승인률·검색에 들지 않는다 |
| 제출본(낸 버전) | `document_upload.designated_deliverable_id` | 항목을 골라 올린 문서. 초안을 확정해야 제출이다(DEC-14). 올리기만 하면 「등록(확정 전)」 |
| 승인(판정) | `work_product` | 지금처럼 제출본의 산출물 버전에 붙는다(UC-031). 현행 버전에만 한다 |

### 2-1. 작업과 묶는 방법

지정은 번호(`wbs_id`)가 아니라 작업 정체(`task_key`, ARC-019)에 묶는다. 계획서를 다시 올려 정체가 이어지면(`CONTINUED`) 지정도 그대로다. 이름이 바뀌거나 쪼개지는 등으로 정체가 끊기면 그 항목은 「재지정 필요」로 따로 모인다. 지정·제출 이력은 지우지 않는다. 발주기관이 지금 계획서의 작업을 골라 다시 정한다(`REASSIGNED` 이력).

### 2-2. 판정 (UC-031 3단계 · UC-033 4단계)

지정 항목이 있는 작업은 WBS 산출물 열 대신 지정 항목으로 판정한다.

- 지정 항목이 모두 제출(확정)됐으면 제출. 근거 문장은 「지정 산출물 n건 중 n건 제출」이다.
- 하나라도 없으면 미제출, 작업 종료일이 지났으면 지연이다.
- 반려된 제출본도 제출로 센다. 제출 여부와 승인 여부는 다른 질문이다.
- 지정이 없는 작업은 지금 규칙(항목에 올린 문서 → 저장소 경로 → 파일 이름 → 유형 이름) 그대로다.

판정은 행(`wbs_item.deliverable_status`)에 남아 시맨틱 지표 `wbs_deliverable_*`·확인 요청 스냅샷·완료 확인 근거가 같은 값을 쓴다.

### 2-3. 권한

지정·고치기·거두기·양식 올리기는 발주기관만 한다(`duties.DELIVERABLE_DESIGNATE`, ARC-032 표에 추가). 플랫폼 관리자는 대신하지 않는다. 양식 내려받기와 이력 보기는 그 사업을 볼 수 있는 사람 모두가 한다. 제출본 올리기는 지금처럼 사업 참여자가 한다.

### 2-4. 지키는 것

- 22종은 분류일 뿐이다. 모든 사업에 고정 필수 목록으로 강제하지 않고, 지정 항목이 아닌 유형으로 내도 막지 않는다(UC-033 E2). 그런 제출은 지정 항목 상태를 바꾸지 않는다.
- WBS 일정·가중치·실적·산출물 열은 편집하지 않는다(IM-001 10절).
- 이행률·승인률·완료 확인율의 산식은 바꾸지 않는다. 승인률 분모(DEC-12 (b) 「WBS 가 정한 산출물」)에 지정 항목을 넣는 것은 이번에 하지 않았다(아래 4절).
- 지정을 거둬도 행과 제출 이력은 남는다(`active=false` + `REMOVED` 이력).

## 3. 화면·API

| 위치 | 내용 |
|---|---|
| 산출물 화면 「발주기관 지정」 열 | 작업마다 「내야 할 산출물 n건」. 펼치면 항목별 상태·분류·작성 안내·양식 내려받기·제출 버전(버전·상태·반려 사유)·지정 변경 이력. 발주기관에게만 지정·고치기·거두기·현행 제출본 승인·반려 |
| 산출물 화면 위 「재지정 필요」 | 계획서 교체로 작업이 끊긴 항목. 예전 작업 이름과 제출 이력, 발주기관에게 작업 고르기 |
| `POST /api/projects/{id}/wbs/designated-deliverables` | 지정 |
| `PATCH …/{did}` · `DELETE …/{did}` | 고치기·재지정 / 거두기 |
| `POST …/{did}/template` · `GET …/{did}/template` | 양식 올리기 / 내려받기 |
| `GET …/{did}/history` | 지정 변경 이력 |
| `POST /api/projects/{id}/documents` 의 `designatedId` | 지정 항목의 제출본으로 올리기 |
| `GET /api/projects/{id}/wbs/deliverables` | 항목에 `taskKey`·`designated`, 응답에 `redesignation` 추가 |

## 4. 대가와 남긴 것

- 양식 파일은 DB(`bytea`, 20MB 까지)에 둔다. PoC 규모에서는 백업·이관이 DB 덤프 하나로 끝나는 쪽이 낫다. 양식이 커지거나 많아지면 문서 볼륨으로 옮긴다.
- 승인률(DEC-12 (b)) 분모를 지정 항목으로 바꾸는 것은 하지 않았다. 지정이 없는 작업은 WBS 산출물 열을 쓰는데, 두 축을 한 분모로 섞는 규칙은 별도 결정이 필요하다.
- 알림(활동 기록)은 기존 판정 전이(제출됨·지연)만 남긴다. 지정 자체의 알림은 두지 않았다.
