# ARC-014 라우팅 캐시: 같은 질문의 판정을 다시 묻지 않는다

| | |
|---|---|
| 상태 | **확정** |
| 일자 | 2026-09-17 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `SWFR.RAG.005` `SWFR.RAG.001` `QUR.RAG.002` · ARC-010 · ARC-013 |

---

## 1. 결정

**질문의 판정(어떤 지표·차원·템플릿·목록 종류인가)만 캐시한다. 값은 캐시하지 않는다.**

한 답변에서 모델을 두 번 부른다. 먼저 판정, 그다음 본문이다. 판정은 값이 아니라 "무엇을 셀지"
라서 데이터가 바뀌어도 그대로 유효하다. 같은 질문이 다시 오면 판정 호출 5~10초가 0 이 되고,
값은 매번 시맨틱 레이어와 표준 모델에서 새로 뽑는다(절대 규칙 1). 시연에서 같은 질문을
되풀이하는 상황에 맞다.

답변 본문 캐시는 하지 않았다. 할 수는 있다. 키에 데이터 버전(마지막 성공 수집 잡·색인 갱신
시각)을 넣으면 안전하다. 다만 판정 캐시만으로 얻는 것이 먼저이고, 본문 캐시는 "값이 바뀌었는데
옛 답을 준다" 를 막는 장치를 더 얹어야 해서 따로 정한다.

## 2. 키

`sha256(카탈로그 버전 + 정규화한 질문)`.

- **정규화**는 공백을 하나로 모으고 앞뒤 공백과 끝 문장 부호(`.?!`)만 뗀다. 그 밖에는 손대지
  않는다. "열린 이슈 목록" 과 "닫힌 이슈 목록" 은 다른 키다. 문장의 유사도로 맞추지 않는다.
  조건 하나가 다른 질문에 같은 판정이 나가는 길이기 때문이다.
- **카탈로그 버전**은 라우팅 시스템 프롬프트 전체의 해시다. 판정은 그 프롬프트에 달려 있으므로
  지표·차원·템플릿 안내·지시문 중 무엇이 바뀌어도 버전이 바뀌고, 옛 판정은 저절로 안 맞는다.
  따로 무효화할 일이 거의 없다.

## 3. 저장하는 것

모델이 낸 **JSON 원본**이다(`route_cache.choice_json`, V29). 파생한 결정이 아니다.

읽을 때 `from_choice` 가 카탈로그로 다시 검증하므로, 캐시된 판정이 가리키는 지표가 폐기되면
그 판정은 문서 경로로 내려간다. 캐시가 카탈로그를 앞서지 못한다. 파싱에 실패한 답은 저장하지
않는다. 어느 모델의 판정인지(`model`)와 적중 횟수·마지막 적중 시각을 함께 남긴다.

## 4. 화면

`QueryRouting.routeCached` 가 참이면 답변 위 경로 표시 옆에 "판정 캐시" 라고 작게 붙는다.
발주기관이 "왜 이번엔 빨랐나" 를 물을 때의 답이다. 값은 새로 뽑았다는 뜻도 그 자리에 있다.

## 5. 끄기와 비우기

`AXLINK_RAG_ROUTE_CACHE=false` 면 매번 묻는다. 비우는 것은 `route_cache.clear()` 이고 관리
화면은 두지 않았다. 버전이 바뀌면 안 맞으므로 대개 손댈 일이 없다.
