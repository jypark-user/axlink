## 9. 파일럿에서 채택할 설계 제약

`CLAUDE.md` 절대 규칙에 추가한다. PRD 6.1.1 「ax-pms 실패 교훈」이 근거이며,
*"프롬프트로 UI를 고쳐도 화면이 변하지 않는"* 문제로 이전 제품이 중단된 실측 기록이다.

1. 대시보드 레이아웃·위젯 상태의 단일 원천은 **서버 DB**. localStorage 금지.
2. 위젯은 코드가 아니라 **데이터**(`spec_json`). 닫힌 유니온 타입 금지.
3. 렌더 경로는 **`spec → 렌더러` 1단계**. 다층 조립 금지.
4. 프론트에 **목업 데이터 파일 금지**. 화면 데이터는 전부 API에서.
5. **데이터 없는 메뉴는 만들지 않는다.** 화면보다 테이블과 수집 경로가 먼저다.
6. 라벨은 발주사 어휘로. 표준 용어 그룹 라벨(`사업 관리 PM` 등) 금지.

## 10. 일정 영향

작업 성격이 **"만들기"에서 "차이 메우기 + 통합"** 으로 바뀐다.

| 구간 | 기존 계획 | 조정 |
|---|---|---|
| W2~W3 | 커넥터 2종 신규 개발 | **조사(D1~D3) + 증분 보완(B1)** → 여유 발생 |
| W4~W5 | 표준화·추적·지표 신규 | **A1 WBS 진척 산정에 집중** |
| W6 | 화면 신규 | **A2 확인 요청 + A3 스냅샷** |
| W7~W9 | RAG·LLM 신규 (버퍼 0) | **C1 모델 전환 + B3 폐쇄망 검증** → 버퍼 확보 |

**버퍼가 없던 W7~W9 구간이 해소된다.** RAG 파이프라인이 이미 동작하므로
남은 일은 모델 전환과 폐쇄망 검증이고, 신규 개발이 아니다.

`RSK-008`(RAG·LLM 구간 버퍼 없음)을 **높음 → 낮음**으로 조정한다.
