## 1. 문제

발주기관 담당자가 가장 먼저 묻는 것은 두 가지다. **사업이 계획대로 가고 있는가**, **내야 할
산출물이 올라와 있는가**. 지금 구조는 이 둘을 축으로 삼지 않는다.

- WBS 는 DB 에 없다. 올린 계획서 파일을 요청 때마다 다시 읽어 진척률만 계산한다. 어느
  표도 WBS 항목을 키로 갖지 않는다.
- 요구사항은 이슈 라벨에서 만든다. 다른 업체 저장소에 붙이면 요구사항이 0 건이고, 이행률은
  상태를 올리는 경로가 없어 언제나 0% 다.
- 이슈와 WBS 사이에 연결이 없다. 설계 문서에는 "WBS 항목과 이슈 연결" 이 적혀 있지만
  구현이 없다.
- 진척률 대표값을 이슈 해결률과 산출물 제출률로 대신 내는 갈래가 있다. 이슈 도구를 잘
  안 쓰는 업체에서는 이 값이 사업 상태와 무관하다.

한마디로 이슈 도구가 중심이고 WBS 는 계산기다. 축이 뒤집혀 있다.

## 2. 결정

**WBS 항목이 사업의 뼈대다.** 진척은 올린 WBS 의 실적 값이고, 산출물은 WBS 항목마다
정해진 것이며, 나머지(이슈·확인 요청·추적관계)는 항목에 딸리거나 딸리지 않은 채 사업
전체 목록으로 남는다.

세 가지 원칙이다.

1. **진척률은 WBS 실적으로만 낸다.** 이슈나 산출물로 진척률을 추정하지 않는다. 그것들은
   옆에 놓고 격차를 경고할 뿐이다.
2. **산출물 제출 여부는 WBS 의 산출물 열이 기준이다.** 항목이 정한 산출물이 저장소나
   업로드 문서에 있으면 제출, 없으면 미제출, 종료일이 지났는데 없으면 지연이다.
3. **이슈는 WBS 에 이어질 수도, 안 이어질 수도 있다.** 이어지지 않은 이슈가 더 많은 게
   보통이다. 그런 이슈는 사업 전체의 이슈 목록으로 그대로 본다. "미배정" 을 결함처럼
   세지 않는다. 문서 작성처럼 구현이 아닌 작업은 이슈가 아예 없을 수 있다. 그런 항목은
   산출물 열로 판정한다(2). 이슈 연결은 있으면 좋은 것이고, 산출물 연결이 기본이다.

요구사항은 이슈에서 만들지 않는다. 원천은 요구사항정의서(문서 정형화 경로)이고, WBS 에
관련 요구사항 열이 있으면 그것으로 항목과 잇는다. 이슈 라벨로 요구사항을 올리는 경로는
연결별 선택 항목으로 내리고 기본은 끈다. 우리 저장소만 요구사항을 GitHub 이슈로 관리하는
시연 케이스라 켜 둔다.

## 3. 데이터 모델

### 3-1. `wbs_item` (신설)

| 열 | 뜻 |
|---|---|
| `project_id`, `wbs_id` | 사업 안에서 유일. `1.3`, `3.2` 같은 WBS 번호 문자열 |
| `parent_wbs_id` | 상위 항목. 번호의 앞부분으로 정한다 |
| `name`, `deliverable` | 업무명, 산출물 열의 원문 |
| `start_on`, `end_on` | 계획기간 |
| `weight` | 가중치. 없으면 말단이 아니다(묶음) |
| `declared_planned`, `actual` | 파일에 적힌 계획·실적. 실적이 진척률의 유일한 재료 |
| `work_product_id` | 이 WBS 를 담은 계획서 버전 |
| `active` | 새 WBS 에서 사라진 항목은 false. 행을 지우지 않는다 |

WBS 를 다시 올리면 같은 `wbs_id` 는 갱신, 새 번호는 추가, 빠진 번호는 `active=false`. 확인
요청과 이슈가 가리키던 항목이 사라지지 않는다.

### 3-2. 산출물 연결

`wbs_item.deliverable` 원문을 그대로 두고, 판정은 조회 때 한다(3-3). 별도 링크 표는 두지
않는다. 산출물 표(`work_product`)와 문서(`document_upload`)는 이미 파일 경로와 이름을 갖고
있어 그것으로 맞춘다.

### 3-3. 산출물 제출 판정

WBS 산출물 열은 업체마다 꼴이 다르다. 세 가지를 차례로 본다. 하나라도 맞으면 제출이다.

1. **저장소 경로.** `docs/20-design/IM-003-SW설계서.md` 처럼 경로 꼴이면 수집된 파일
   (`work_product.file_uri`, GitHub contents 수집분)에 같은 경로가 있는가.
2. **파일 이름.** 경로가 아니면 올린 문서(`document_upload.file_name`)나 산출물 제목에 같은
   이름(확장자 무시)이 있는가.
3. **산출물 유형.** "사업수행계획서" 처럼 29110 산출물 유형 이름이면 그 유형의 현행
   산출물이 있는가.

맞는 게 없으면 미제출. `end_on` 이 오늘보다 앞이면 지연. 판정 근거(어느 규칙, 어느 파일)를
함께 돌려준다. 발주기관이 "왜 제출로 보나" 를 물었을 때 답이 있어야 한다.

### 3-4. 이슈 배정

`issue.wbs_item_id` (nullable). 배정 근거는 **그 사업의 WBS 번호 집합과 정확히 일치하는
토큰**뿐이다.

- 라벨: `WBS: 3.2`, `wbs-3.2`, `3.2`
- 제목 앞머리: `[3.2] ...`, `3.2 ...`
- Redmine 커스텀 필드 `WBS ID`

번호 집합에 없는 값은 잇지 않는다. 추측하지 않는다. 배정된 이슈는 항목 화면에 딸려 나오고,
배정되지 않은 이슈는 사업 이슈 목록에 그대로 있다. 둘의 합이 전체 이슈다.

추적관계(`trace_link`) 대상 유형에 `WBS_ITEM` 을 더한다. 근거 유형은 `TEXT_WBS_ID`.
기존 요구사항·산출물·코드변경 규칙은 그대로다.

### 3-5. 요구사항

- `requirement` 의 원천은 문서(요구사항정의서 정형화 확정)가 기본이다.
- 연결 설정 `requirement_from_issues` (기본 false). true 면 지금 규칙(라벨·제목 코드)대로
  이슈에서도 만든다. 우리 저장소 연결만 true.
- `wbs_item.requirement_codes` 는 두지 않는다. WBS 에 관련 요구사항 열이 있으면 파서가
  코드를 뽑아 `trace_link(WBS_ITEM → REQUIREMENT, TEXT_REQ_CODE)` 로 잇는다.

## 4. 진척·지연·격차

- 대표 진척률 = Σ(말단 가중치 × 실적). 지금 L1 그대로. 이슈·산출물 갈래는 대표값에서
  뺀다.
- 계획선은 기간 안분 그대로.
- **지연 항목** = 실적이 계획선보다 20%p 이상 뒤진 항목, 또는 종료일이 지났는데 실적이
  100 미만인 항목.
- **격차 경고** = 항목 실적이 높은데(80 이상) 산출물이 미제출이거나 열린 이슈가 있는 경우.
  경고일 뿐 진척률을 깎지 않는다.
- 산출물 현황 = 말단 항목 중 산출물이 정해진 것을 분모로 제출·미제출·지연 건수.

## 5. 화면과 질의

- 사업 첫 화면: 진척률(계획 대비), 산출물 제출 현황(제출/미제출/지연), 지연 항목 목록,
  그 다음에 이슈 요약. 이 순서가 발주기관의 질문 순서다.
- WBS 항목 화면: 실적·계획, 산출물 판정과 근거, 딸린 이슈, 확인 요청, 요구사항 링크.
- 자연어 질의: "3.2 는 어떻게 되고 있어?", "설계서는 올라왔어?", "늦은 작업은?" 이 WBS
  항목 표와 산출물 판정으로 답한다. 이슈 목록 질문은 지금처럼 이슈 표로 답한다.

## 6. 우리 저장소에 미치는 것

자기참조 원칙상 우리 이슈에도 WBS 번호를 단다. 작업 규약(CLAUDE.md §2)에 "이슈는 관련
WBS 번호를 라벨 `WBS: n.n` 으로 단다. 없으면 달지 않는다" 를 넣는다. 소급이 안 되므로
이 문서가 확정되는 즉시 적용한다(2026-09-21 확정, 같은 날 말단 34개의 라벨을 만들었다).
라벨은 WBS 말단 번호와 같은 이름이어야 하고, 항목이 하나뿐일 때만 단다. 두 항목에 걸치면
더 큰 쪽을 고른다.

## 8. 버린 대안

- **이슈에서 진척률 추정.** 이슈 도구를 성실히 쓰는 업체에서만 맞는다. 발주기관이 보는
  기준선은 계약 문서인 WBS 여야 한다.
- **미배정 이슈를 결함으로 표시.** 대부분의 이슈는 WBS 와 무관하다. 경고가 늘 켜져 있으면
  아무도 안 본다.
- **WBS 항목과 산출물 링크 표.** 산출물 열이 자유 텍스트라 링크를 미리 만들 수 없다. 조회
  때 판정하고 근거를 같이 내는 편이 정직하다.
- **이슈 본문에서 WBS 번호 추정.** 번호 꼴이 목록 번호와 구분되지 않는다. 라벨·제목
  앞머리·필드만 본다.
