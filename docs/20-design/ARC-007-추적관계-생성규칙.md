# ARC-007 추적관계 생성 규칙

| | |
|---|---|
| 상태 | **확정** |
| 일자 | 2026-09-14 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `SWFR.PIP.003` `SWFR.PIP.004` `QUR.PIP.001` `SWFR.WEB.002` |

---

## 1. 결정

**추적관계는 원본에 사람이 남긴 명시적 근거에서만 만든다.** 근거가 없으면 만들지 않는다.
비슷해 보인다는 이유로 잇지 않는다(유사도 추론은 요구사항정의서 9절, 제안 항목으로 분리).

링크마다 근거 유형, 근거가 적힌 원문 한 줄, 원문의 위치(URL)를 같이 저장한다. 발주기관
담당자가 추적표의 칸 하나를 눌렀을 때 "왜 이어졌는가"를 원문으로 확인할 수 있어야 한다.

생성은 수집 뒤 자동으로 돌고, 몇 번을 돌려도 결과가 같다. 링크는 `trace_link` 테이블
한 곳에 두고 근거 컬럼은 V24 로 붙였다.

## 2. 근거 유형과 판별 규칙 (SWFR.PIP.003 · SWFR.PIP.004)

| 근거 유형 | 어디서 읽는가 | 무엇을 잇는가 | 근거 원문 |
|---|---|---|---|
| `TEXT_REQ_CODE` | 커밋 메시지, PR 제목·본문, GitHub 작업 이슈 제목·본문, Redmine 이슈 제목·본문에 적힌 요구사항 코드 | 커밋·PR·이슈 → 요구사항 | 코드가 적힌 그 줄 |
| `TEXT_ISSUE_REF` | 커밋 메시지·PR 본문의 `GH-n` / `RM-n` | 커밋·PR → 이슈 (또는 그 번호가 요구사항 이슈면 요구사항) | 참조가 적힌 그 줄 |
| `CUSTOM_FIELD` | Redmine 이슈의 커스텀 필드 `REQ ID` (필드 이름은 연결별 설정, SWFR.CON.002) | Redmine 이슈·리스크 → 요구사항 | `REQ ID: SWFR.CON.004` |
| `ISSUE_RELATION` | Redmine issue relations | Redmine 이슈 → Redmine 이슈 | `relates RM-5` |
| `TEXT_FILE_PATH` | 커밋·PR·이슈 본문에 적힌 산출물 파일 경로 (수집 설정에 있는 경로만) | 커밋·이슈 → 산출물, 요구사항 이슈 본문이면 산출물 → 요구사항 | 경로가 적힌 그 줄 |

**요구사항 코드의 인정 범위.** 점으로 이어진 대문자 묶음(`SWFR.CON.004` 꼴)을 후보로 보고,
그 사업의 요구사항 목록에 실제로 있는 코드만 인정한다. 오타난 코드로는 링크가 생기지 않는다.
요구사항 목록에 없는 코드는 "가리킨 상대가 없는 근거"로 세기만 하고 버린다.

**이슈 참조의 인정 범위.** 도구 접두가 붙은 `GH-n` / `RM-n` 만 읽는다. 맨 `#17` 은 GitHub 인지
Redmine 인지 구분되지 않아 근거로 쓰지 않는다(작업 규약 3절과 같은 이유). 참조한 이슈가
표준 모델에 없으면(수집 범위 밖) 링크를 만들지 않는다. 이슈끼리 서로를 `GH-n` 으로 언급한
것은 추적표의 축이 아니라 읽지 않는다.

**링크 종류(설계·구현·시험·납품)는 출발점의 성격이 정한다.**

| 출발점 | 판단 근거 | 종류 |
|---|---|---|
| 커밋·PR | 제목의 유형이 `test` | `TESTS` |
| 커밋·PR | 그 외 | `IMPLEMENTS` |
| GitHub 이슈 | 라벨 `유형: 설계` / `유형: 시험` | `DESIGNS` / `TESTS` |
| Redmine 이슈·리스크 | 트래커 `설계` / `시험` | `DESIGNS` / `TESTS` |
| 이슈 (그 외) | | `IMPLEMENTS` |
| 산출물 | 자리가 SW설계서 / 시험 문서 | `DESIGNS` / `TESTS` |
| 산출물 (그 외) | | `DELIVERS` |

**방향.** 요구사항은 언제나 도착점이다. "커밋이 요구사항을 구현한다", "이슈가 요구사항을
시험한다"로 읽는다. 요구사항 목록의 `traceComplete` 와 사업 지표의 추적 커버리지(시험 링크가
있는 요구사항의 비율)가 같은 방향으로 센다. 요구사항끼리는 잇지 않는다.

## 3. 멱등성과 끊김 (QUR.PIP.001)

멱등 키는 `trace_link` 의 기존 유니크 제약 `(from_type, from_id, to_type, to_id, link_kind)` 다.
같은 변이 다시 나오면 행을 새로 만들지 않고 근거만 갱신한다. 한 변에 근거가 여럿이면
(예: 커밋 제목의 `[SWFR.CON.002]` 와 본문의 `Refs: GH-2` 가 같은 요구사항을 가리킬 때)
먼저 찾은 것을 남긴다. 원본 순서가 곧 우선순위다.

생성은 **사업 단위**로 돈다. 커밋(GitHub)이 Redmine 이슈를 가리키고 Redmine 이슈가 GitHub
요구사항을 가리키므로 연결 하나만 보고는 양 끝을 못 찾는다. 어느 연결이든 수집이 끝나면
그 사업의 원본 전부를 다시 훑는다.

이번 생성에서 근거가 다시 확인되지 않은 자동 링크는 지우지 않고 `BROKEN` 으로 표시한다.
이슈 본문에서 코드를 지웠다면 그 링크는 끊긴 것으로 남는다. 언제 근거가 사라졌는지가
남아야 감독 기록이 된다. 근거가 되돌아오면 같은 행이 다시 `ACTIVE` 가 된다.

사람이 만든 링크(`origin = MANUAL`)는 자동 생성이 덮지 않는다. 같은 변이 있으면 자동
근거를 적지 않고 건너뛴다. 자동 링크는 근거 없이 존재할 수 없다. DB 제약
`ck_trace_link__auto_evidence` 가 이를 강제한다.

## 4. 조회 (SWFR.WEB.002)

| 경로 | 내용 |
|---|---|
| `GET /api/projects/{id}/traceability` | 요구사항 한 줄에 설계·구현·시험 칸. 칸의 항목마다 원문 링크가 붙고, 끊긴 링크가 있는 칸은 `brokenAt` 로 표시 |
| `GET /api/projects/{id}/requirements/{rid}` | 요구사항 하나와 걸린 링크 전부. 링크마다 근거 유형·근거 원문·원문 위치 |

메뉴 화면과 AI 질의가 같은 함수를 쓴다. 수치가 어긋나면 버그다.

## 5. 검토한 대안

**연결 단위 생성.** 승격과 같은 흐름이라 단순하지만, 도구를 가로지르는 링크(커밋 → Redmine
이슈 → GitHub 요구사항)를 못 만든다. 사업 단위로 바꿨다. 원본 수는 PoC 규모(페이지 상한)라
매번 전부 훑어도 부담이 없다.

**끊긴 링크 삭제.** 표가 깨끗해지지만 "언제부터 근거가 없어졌는가"를 잃는다. 상태만 바꾼다.

**맨 `#n` 참조 인정.** GitHub 만 쓰는 업체라면 `#12` 가 곧 GitHub 이슈다. 그러나 두 도구를
같이 쓰는 순간 어느 쪽인지 알 수 없고, Redmine 은 저장소를 연결하면 `#n` 을 자기 이슈로
읽는다. 잘못 잇는 것보다 안 잇는 쪽이 QUR.PIP.001 에 맞다.

**커밋 본문 대신 `code_change.title` 만 읽기.** 표준 모델만 보면 되어 단순하지만 `Refs:` 줄은
본문에 있다. 근거는 원본(`raw_artifact`)에서 읽고 링크의 양 끝만 표준 모델 id 로 적는다.

## 6. 대가

작성 규약을 지키지 않은 업체의 데이터에서는 링크가 적게 나온다. 그것은 이 규칙의 한계가
아니라 사실의 반영이다. 추적표가 비어 있다는 것 자체가 발주기관이 알아야 할 현황이다.
규약 없이도 생기는 링크(Redmine relations, REQ ID 필드)를 우선 안내한다.

GitHub 가 PR 본문의 `Closes #n` 으로 만드는 이슈·PR 연결은 REST 목록 API 에 실려 오지 않아
아직 읽지 않는다. 필요해지면 PR 상세 조회를 추가한다.

작업 이슈끼리의 참조, 요구사항끼리의 참조는 추적표의 축이 아니라 만들지 않는다. 필요해지면
근거 유형을 하나 더 두는 일이지 규칙을 바꾸는 일은 아니다.

## 개정 (2026-10-13)

저장소 설계 문서의 명시적 참조를 설계 근거(`DOC_REQ_REF`, 출발점 `REPO_DOCUMENT`)로 더하고, 커밋·PR 을
변경 파일로 분류하며, 다시 확인되지 않은 링크를 대체·제외(`SUPERSEDED`)와 끊김(`BROKEN`)으로 나눈다.
상세는 ARC-024. 이 문서의 나머지 규칙(명시적 근거만, 유사도 금지, 수동 링크 보존)은 그대로다.
