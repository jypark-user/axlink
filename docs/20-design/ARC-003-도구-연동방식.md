## 1. 결정

**수집 계층은 각 도구의 REST API 를 직접 호출한다.** MCP·웹훅·DB 직결은 쓰지 않는다.

모든 도구는 공통 포트(`ToolConnector`) 뒤에 어댑터로 붙는다. 새 도구 연동의 비용은
**어댑터 구현체 1개 + 등록소 1줄 + `tool` CHECK 마이그레이션 1줄**이다.

## 2. 공통 인터페이스 (SWFR.CON.001)

`app/integration/port.py` 가 계약이다. 상위 계층(등록·수집)은 이것만 안다.

| 계약 | 의미 |
|---|---|
| `tool` | `tool_connection.tool` 값. 등록소의 키 |
| `item_kinds` | 수집 항목종류 선언. 도구 어휘 그대로 `raw_artifact.object_kind` 에 적힌다 |
| `verify(base, target, secret)` | 대상에 닿는지 + **항목종류별로 실제 읽히는지**. 권한 결손이 붙이는 시점에 드러난다 |
| `fetch_items(…, kind, …)` | (외부 ID, 원본 payload) 반복자. **원본은 가공하지 않는다** |
| `fetch_file(…, path)` | 저장소 파일 수집(WBS 경로). 파일 개념이 없는 도구는 `None` |

자격증명은 **복호화된 비밀 문자열 하나**로 넘기고 해석은 어댑터 책임이다. 도구마다
인증 방식이 달라(아래 표) 상위 계약에 인증 형태가 스며들면 도구 추가마다 계약이 흔들린다.

원본 적재(내용해시 멱등)와 표준 모델 승격이 분리되어 있으므로, 도구별 차이는
어댑터(가져오기)와 매핑(표준화) 두 곳에만 존재한다. 매핑은 Redmine 어댑터를 붙이며
`mapping/{github,redmine}` 으로 가른다.

## 3. 도구별 연동 방식

### 범위 내 (M1 확정 — 대표 도구 2종)

| | GitHub (가동) | Redmine (M2) |
|---|---|---|
| 프로토콜 | REST v3, JSON | REST, JSON |
| 인증 | PAT — `Authorization: Bearer` | API 키 — `X-Redmine-API-Key` 헤더 |
| 대상 지정 | `owner/repo` | 프로젝트 식별자 |
| 수집 항목 | issue · pull_request · commit · 파일(contents) | issue(journals·relations 포함) · version · tracker · membership |
| 증분 | `since=`(updated 기준) · commits `since=` | `updated_on=%3E%3D<ISO8601>` 필터 |
| 페이지 | `per_page` ≤ 100 | `limit` ≤ 100 + `offset` |
| 표준 매핑 요지 | 라벨 「유형: 요구사항」→ 요구사항, PR·커밋 → 코드변경 | Version → 마일스톤, Issue relations → 추적관계, 커스텀 필드 `REQ ID` → 도구 횡단 접착제 |
| 주의 | 사설 GHES 도 base URL 만 다르다 | REST API 가 기본 **비활성** — 관리 → 설정 → API 에서 켜야 한다 |

### 범위 밖 (확장 검증용 — 어댑터 추가만으로 붙는지의 척도)

| | GitLab | Jira |
|---|---|---|
| 프로토콜 | REST v4 | REST v3 |
| 인증 | PAT — `PRIVATE-TOKEN` 헤더 | Basic — email + API 토큰 |
| 수집 항목 | issue · merge_request · commit · 파일 | issue(JQL) · version · issuelink |
| 증분 | `updated_after=` | JQL `updated >=` |
| 추가 비용 | 어댑터 + 등록 1줄 + CHECK 1줄 | 좌동. Basic 쌍은 비밀 문자열 하나에 담아 어댑터가 해석 |

## 4. 검토한 대안

**MCP** — LLM 이 도구를 호출할 때의 프로토콜이다. 수집은 LLM 이 개입하지 않는
결정론적 배치라 쓸 자리가 아니다(절대 규칙 1 — 수치는 집계에서만). MCP 서버를 끼우면
폐쇄망 반입 요소가 늘고, 수집 경로의 감사가능성이 떨어진다. AI 질의 계층에서도
데이터 조회는 시맨틱 레이어가 맡으므로 현 구조에서는 채택 지점이 없다.

**웹훅(푸시)** — 원천 도구에 설정을 만들어야 한다. 용역사 도구에 무언가를 심는 것은
읽기 전용 원칙(`QUR.CON.001`)의 정신과 어긋나고, 폐쇄망에서 인바운드 경로를 여는
부담이 있다. PoC 규모에서는 풀 방식 증분 수집(`SWFR.CON.005`)으로 충분하다.

**DB 직결** — Redmine DB 를 직접 읽는 방식. 스키마가 공개 계약이 아니라서 버전 업그레이드에
깨지고, 필요 이상의 권한을 요구한다. 배제한다.

## 5. 대가

REST 풀 방식이므로 실시간성이 없다 — 수집 주기만큼 화면이 늦는다. 발주기관 감독 업무는
일 단위 판단이라 감수한다. 도구별 API 율한(rate limit)은 PoC 규모(페이지 상한)에서는
닿지 않지만, 증분 수집 구현 시 `Retry-After` 존중을 어댑터 공통 규칙으로 둔다.
