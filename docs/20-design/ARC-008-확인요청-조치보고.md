# ARC-008 확인 요청과 조치 보고

| | |
|---|---|
| 상태 | **확정** |
| 일자 | 2026-09-14 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `SWFR.WEB.004` `SWFR.WEB.005` `SWFR.WEB.006` `QUR.WEB.003` `SER.SEC.003` |

---

## 1. 결정

**발주기관과 용역사 사이의 관리 순환을 AX Link 안에서 닫는다.** 발주기관이 확인이 필요한
항목을 짚어 요청하고, 용역사가 조치 결과를 보고하고, 발주기관이 확인해 닫는다. 요청 시점의
대상 상태를 시스템이 떠 두고, 보고 시점에 그때와 지금을 나란히 놓는다. 원천 도구에는 아무것도
쓰지 않는다.

파일럿에서 승계한 변경요청·시정조치 화면은 대응 요구사항이 없어 이 화면으로 바꿨다.
`change_request`·`correction_action` 테이블은 그대로 두되(ARC-005 "테이블만 있다") 메뉴에서
뺐다.

## 2. 대상과 상태

요청은 다섯 종류의 대상에 건다. 종류마다 "상태"라고 부를 값이 다르므로 종류별로 뜨는 값을
정해 둔다. 전부 표준 모델이나 WBS 파일, 진척 집계에서 읽은 값이다.

| 대상 | 키 | 떠 두는 값 |
|---|---|---|
| WBS 항목 | WBS ID | 실적률, 계획률, 연결 산출물, 종료일 |
| 산출물 | 산출물 유형 코드(22종) | 상태, 버전, 제목, 제출일, 승인일, 파일 |
| 이슈 | issue.id | 상태, 심각도, 담당, 해결일 |
| 리스크 | risk.id | 상태, 심각도, 담당, 종료일 |
| 지표 | REPRESENTATIVE, PROGRESS_WBS, PROGRESS_ISSUE, PROGRESS_WORK_PRODUCT | 값, 분자, 분모 (대표값은 산정 수준과 근거) |

산출물의 키가 행 ID 가 아니라 유형 코드인 이유는 버전이 쌓이면 행이 바뀌기 때문이다.
"사업수행계획서"를 짚은 요청은 다음 버전이 올라와도 같은 항목을 가리켜야 한다.

## 3. 상태 흐름과 역할

```
요청(REQUESTED)  --용역사 보고-->  조치보고(REPORTED)  --발주기관 확인-->  확인완료(CONFIRMED)
                                       |
                                       +--발주기관 다시 요청-->  요청(REQUESTED)
```

- 요청 등록, 확인완료, 다시 요청은 발주기관(CLIENT)만 한다. 조치 보고는 용역사(CONTRACTOR)만 한다.
  역할이 맞지 않으면 403 이다.
- 다시 요청은 같은 요청 안에서 돈다. 보고·확인 칸을 비우고 요청 시점 상태를 새로 뜨며,
  `rerequest_count` 를 올린다. 지난 보고는 이력 테이블에 남는다.
- 미처리 건수(확인완료가 아닌 것)를 사업 목록과 사업 상세에 붙인다(`openReviewRequestCount`).

## 4. 저장 구조 (V26)

`review_request` 가 현재 상태 한 줄, `review_request_event` 가 요청·보고·확인·재요청이 오간
순서다. 요청 시점 상태는 `snapshot_json`, 보고 시점 상태는 `report_snapshot_json` 에 둔다.
이벤트 행마다 그 시점 상태를 따로 갖는다. 재요청으로 현재 행이 덮여도 이력에서 지난 보고와
그때 상태를 되짚을 수 있다.

변경 내역은 저장하지 않고 조회 때 계산한다. 요청 시점 스냅샷과 지금 상태를 같은 함수로
뜨고 다른 키만 골라낸다. 저장해 두면 대상이 그 뒤에 또 바뀌었을 때 낡은 값을 보여 주게 된다.

## 6. 검토한 대안

**변경요청·시정조치 화면을 그대로 쓰기.** 파일럿 화면은 용역사가 변경을 신청하고 발주기관이
승인하는 방향이라 요구사항(발주기관이 묻고 용역사가 답한다)과 반대다. 상태값도 다르다. 바꾸는
편이 요구사항에 맞다.

**변경 내역을 보고 시점에 저장.** 보고 직후에는 맞지만 그 뒤 대상이 또 바뀌면 화면이 낡는다.
계산은 매번 몇 행 읽는 비용뿐이라 저장하지 않는다.

**원천 도구(Redmine 등)에 요청을 이슈로 남기기.** QUR.WEB.003 위반이다. 발주기관 화면은
읽기 전용이고 원천에 흔적을 남기지 않는다.

## 7. 대가

대상이 사라지면(이슈가 도구에서 지워져 승격 대상에서 빠지는 경우) 지금 상태가 비어 나온다.
요청 자체는 남으므로 무엇을 물었는지는 보이지만 차이 계산은 되지 않는다. 지표 대상은 진척
집계를 그때그때 돌리므로 WBS 파일이 큰 사업에서는 조회가 느릴 수 있다. PoC 규모에서는 문제되지
않는다.
