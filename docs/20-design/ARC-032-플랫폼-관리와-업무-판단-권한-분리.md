## 1. 문제

플랫폼 관리자(`SUPER_ADMIN`)의 권한이 행위마다 달랐다.

- 기준선 확정·돌려보내기와 명세서 등록·정리·제출은 관리자도 했다(ARC-028). 확정 역할을 남겨 화면에 「(관리자)」로 보였다.
- 요구사항 상태 지정, 산출물 승인·반려, 일반 확인 요청 등록은 관리자도 했다(ARC-025, ARC-019, ARC-029 「발주기관과 같은 권한」).
- 확인완료·다시 요청, 작업 완료 확인 요청·확인·철회는 관리자가 못 했다(ARC-019).

이 차이는 원칙에서 나온 것이 아니라 기능을 만든 순서에서 나왔다. 관리자가 발주기관의 판단을 대신하면 「발주기관이 확인했다」「발주기관이 승인했다」는 기록이 사실이 아니게 된다. 이행률·승인률·완료 확인율이 그 기록을 세므로 수치의 근거도 흔들린다.

## 2. 결정

**플랫폼 관리 권한과 발주기관·용역사의 업무 판단 권한을 나눈다.** 관리자는 모든 사업을 보고 플랫폼을 관리하지만, 업무 판단은 하지 않는다.

### 2-1. 업무 판단 권한표

서버의 단일 원천은 `app/auth/duties.py` 의 `DUTIES` 다. 서비스는 `duties.require()` 로 묻고, 화면은 같은 표대로 버튼을 보인다. 사업 접근(그 사업의 발주기관인지, 배정된 용역사인지)은 서비스가 따로 본다.

| 행위 | UC | 발주기관 | 용역사 | 관리자 | 이전 관리자 권한 |
|---|---|---|---|---|---|
| 요구사항 명세서 등록·항목 정리·등록 취소·제출 | UC-020 | 거절 | **함** | 거절 | 했다 |
| 요구사항 목록 확정·돌려보내기 | UC-021 | **함** | 거절 | 거절 | 했다 |
| 요구사항 상태 지정·되돌림 | UC-023 | **함** | 거절 | 거절 | 했다 |
| 산출물 승인·반려 | UC-031 | **함** | 거절 | 거절 | 했다 |
| 작업 완료 확인 요청·확인·철회 | UC-032 | **함** | 거절 | 거절 | 못 했다(그대로) |
| 작업 완료 보고 · 확인 요청 조치 보고 | UC-032 · UC-051 | 거절 | **함** | 거절 | 못 했다(그대로) |
| 확인 요청 등록(일반) | UC-050 | **함** | 거절 | 거절 | 했다 |
| 확인완료·다시 요청 | UC-052 | **함** | 거절 | 거절 | 못 했다(그대로) |
| WBS 작업별 산출물·양식 지정·고치기·거두기 | UC-033 | **함** | 거절 | 거절 | 없던 기능(11-16 추가, ARC-033) |

관리자가 거절될 때는 각 행위의 거절 문구 뒤에 「플랫폼 관리자는 발주기관·용역사의 업무 판단을 대신하지 않습니다.」가 붙는다. 역할 검사는 대상 조회보다 먼저 한다.

### 2-2. 관리자에게 남는 플랫폼 관리

아래는 이번 결정으로 바뀌지 않는다. 업무 판단이 아니라 운영이다.

| 영역 | 내용 | 근거 |
|---|---|---|
| 조직·계정 | 발주기관 조직과 담당자 계정 발급·중지, 비밀번호 재설정 | IM-003 10절 |
| 사업 관리 | 사업 만들기, 참여 업체·사용자 할당·초대, 연결 소유 업체 변경 | ARC-029 |
| 수집 | 수집 주기 변경, 일별 스냅샷 수동 기록 | SWFR.PIP.005 |
| 화면 구성 | 대시보드 위젯 편집, 인포 템플릿 | SWFR.WEB.002 |
| 플랫폼 | AI 모델 설정, 서버 오류 기록 | IM-003 |
| 조회 | 모든 사업의 모든 화면 | AC-040-1 |

사업 관리는 운영 지원을 위해 관리자도 할 수 있지만, 평소에는 그 사업의 발주기관이 한다.

### 2-3. 과거 기록

권한표가 바뀌어도 이미 남은 기록은 지우거나 고치지 않는다.

- 기준선 확정 기록은 확정 역할(`confirmed_by_role`)을 지니고 있어 관리자가 확정한 것은 계속 「(관리자)」로 보인다.
- 요구사항 상태 지정은 지정한 계정의 역할을 응답(`decision.decidedByRole`)에 더해, 관리자가 지정한 것은 「(관리자)」로 보인다. 저장된 값은 그대로다.
- 2026-11-16 기준 실제 기록: 5173·5174 DB 모두 관리자가 지정한 요구사항 상태 1건씩이 있고, 관리자가 확정한 기준선·승인한 산출물·연 확인 요청·남긴 완료 확인은 없다.

## 3. 화면

| 화면 | 관리자에게 보이는 것 |
|---|---|
| 요구사항 등록·확정 | 목록과 상태만. 등록·정리·제출·확정·돌려보내기 버튼 없음 |
| 추적표 · 요구사항 상세 | 상태 지정 버튼 없음. 예전 관리자 지정은 「이름(관리자)」 |
| 산출물 | 승인·반려 버튼 없음 |
| 확인 요청 | 요청 등록·조치 보고·확인완료·다시 요청 버튼 없음. 머리말은 「확인 요청과 조치 기록을 봅니다. 플랫폼 관리자는 요청·보고·확인을 대신하지 않습니다.」 |

## 4. 대가

- 시연·복구에서 관리자 계정 하나로 흐름을 끝까지 돌릴 수 없다. 발주기관·용역사 계정을 각각 써야 한다.
- 발주기관 담당자가 자리를 비우면 판단이 늦어진다. 대리 판단이 필요하면 그 발주기관 조직에 계정을 하나 더 발급한다(관리자가 대신하지 않는다).
