## 1. 결정

**AI 답변의 본문 안에 인포 템플릿을 끼운다.** 모델은 본문에 `[그림 N]` 표식만 놓고, 그 자리에
그려질 값은 전부 서버가 만든다. 그림은 여러 장일 수 있다.

값의 출처는 둘이다.

| 블록 | 값이 어디서 오나 | 그림 |
|---|---|---|
| 집계 | 시맨틱 레이어의 SQL 집계. 모델이 지표·차원·템플릿을 고른다 | 카탈로그가 고른 템플릿 |
| 목록 | 표준 모델 테이블(`issue` `requirement` `risk` `work_product`)의 행 | `DATA_TABLE` |

모델이 쓰는 것은 표식과 문장뿐이다. 표의 행도 집계 값도 모델을 거치지 않는다(절대 규칙 1).

## 2. 왜 목록을 표준 모델에서 꺼내나

**청크 근거로는 상태 조건을 못 건다.** 색인된 청크에는 제목과 본문만 있고 상태가 없다.

09.17 실측. "현 사업에서 아직 작업이 안된 이슈목록 조회해줘" 를 물으면 종류로 모은 청크
11건이 근거로 들어갔고, 모델은 그중 닫힌 이슈 3건(D1 조사·D2 조사·E 파일럿 인수 빌드·기동
확인)을 "작업이 안 된" 목록에 섞었다. 근거 게이트는 통과했고 수치 검문도 걸지 못했다.
근거에 상태가 없으니 검문할 대상 자체가 없었다.

표준 모델에는 상태가 있다. 이슈 화면이 읽는 것과 같은 테이블을 같은 조건으로 읽으면 값도
필터도 SQL 이 정한다. "메뉴 접근과 자연어 질의는 같은 데이터를 쓴다" 는 원칙이 이 경로에서
성립한다. 같은 질문을 다시 물었을 때 표에는 열린 7건만 들어왔다.

## 3. 흐름

```
질문 → 라우팅(JSON)  route · measure · dimensions · template · list · listFilter
        ├─ measure 가 카탈로그에 있으면      → 집계 블록 (시맨틱 레이어)
        └─ list 가 있으면                    → 목록 블록 (표준 모델 조회)
     → 프롬프트에 "## 그림 N" 절과 "## 그림 놓기" 지시
     → 생성. 본문에 [그림 N] 표식
     → SSE infographic 이벤트를 블록마다 (slot 포함)
     → 프런트가 본문의 표식 자리에 위젯 렌더러를 끼운다
```

`listFilter` 는 `OPEN`(아직 안 끝난 것) · `CLOSED`(끝난 것) · `ALL` 셋이다. 종류마다 무엇이
"끝난 것" 인지는 `entity_table.EntitySpec` 이 SQL 조각으로 들고 있다. 이슈는
`RESOLVED·CLOSED`, 요구사항은 `VERIFIED·ACCEPTED`, 리스크는 `CLOSED`, 산출물은 `APPROVED` 다.

집계와 목록은 따로 판정한다. 둘 다 오면 그림이 두 장이다("이슈 몇 건이고 목록도 줘").

## 4. 지켜야 했던 것들

**근거 게이트는 표를 근거로 인정한다.** 표를 만들었으면 청크 유사도가 문턱을 못 넘어도
답한다. 표의 행은 SQL 이 꺼낸 것이라 지어낸 값이 아니다. 색인이 비어 있어도 목록 질문에
답할 수 있다. 청크도 없고 표도 없을 때만 막는다(SWFR.RAG.007 그대로).

**수치 검문은 표의 행과 범위 문장을 근거에 넣는다.** 본문이 "총 7건" 이라고 쓰면 표의 범위
문장이 그 근거다. 그리고 `[그림 1]` 의 1 은 수치가 아니므로 각주 번호와 같이 검문 전에
걷어낸다. 안 그러면 멀쩡한 답에 경고가 붙는다.

**표가 있으면 같은 목록을 청크로 또 넣지 않는다.** 09.17 실측에서 요구사항 41건이 표와 청크
양쪽으로 프롬프트에 들어가 모델이 120초를 넘겨 끊겼다. 표를 만든 종류는 일반 검색으로 출처만
찾는다.

**프롬프트에는 표의 앞 8줄만 넣는다.** 본문은 목록을 다시 나열하지 않으므로 성격을 알 만큼만
있으면 된다. 전체는 그림이 들고 있다. 검문의 근거는 잘리지 않은 전체를 쓴다.

**값이 하나뿐이면 그림을 붙이지 않는다.** "이슈가 몇 건이야?" 의 답은 "7건입니다" 한 문장으로
끝난다. 숫자 카드까지 붙이면 답이 괜히 무거워진다. 집계 결과의 값이 둘 이상일 때(범주별·기간별)만
그림을 붙인다. 값은 그림 없이도 프롬프트와 수치 검문에 그대로 들어간다. 목록 표와 현황 그림은
이 규칙을 타지 않는다. 목록은 표가 답이고, 현황은 그림이 목적이다.

**표식은 표식만.** 경량 모델은 지시문의 예시를 그대로 베낀다. `[그림 1]=처리 중 이슈` 라고
쓴 사례가 있어서, 지시를 "`[그림 1]` 이라고만 쓴다. 표식 뒤에 등호나 제목을 붙이지 않는다"
로 고쳤다. 본문이 표식을 안 쓰면 답변 끝에 붙인다. 만든 그림을 조용히 버리지 않는다.

## 5. 저장 (V28)

`message.infographic_json` 이 그림 하나를 담은 객체였다. 이제 블록 목록을 담는다. 스키마는
`jsonb` 그대로고 안의 모양만 바뀌므로 기존 행을 한 번 배열로 펴 두고 CHECK 로 고정했다.
읽는 코드는 옛 객체도 받아 준다.

API 의 `MessageResponse.infographic` 은 `infographics` 목록이 됐다.

## 6. 실측 (09.17 · gemma4:31b-cloud)

| 질문 | 라우팅 | 그림 | 시간 |
|---|---|---|---|
| 현 사업에서 아직 작업이 안된 이슈목록 조회해줘 | ISSUE · OPEN | 표 7행 (닫힌 것 없음) | 69초 |
| 완료된 이슈는 뭐가 있어? | ISSUE · CLOSED | 표 4행 | 60초 |
| 요구사항 목록 보여줘 | REQUIREMENT · ALL | 표 41행 | 96초 |
| 등록된 리스크 목록 보여줘 | RISK · ALL | 없음 (데이터 0건) | 10초 |

본문은 "처리 중인 이슈는 총 7건으로, 대부분 심각도 MAJOR이며 … [그림 1]" 처럼 건수와 요점
한 문장에 표식이다.

남은 한계. 모델이 목록 질문을 목록으로 안 보는 경우가 있다("미제출 산출물 목록"). 라우팅
프롬프트의 예시를 늘려 줄이고 있으나 경량 모델에서는 완전하지 않다. 생성 시간이 60~100초라
`AXLINK_LLM_TIMEOUT` 기본값 120초에 가깝다. 모델별 생성 상한과 시간 제한은 ARC-011 의 설정
화면에서 조정한다.

## 7. 범위 밖

- 근거 문서의 문장을 표로 재구성하는 블록은 하지 않는다. 값을 모델이 옮겨 적는 형태라 절대
  규칙 1과 수치 검문 설계를 다시 열어야 한다.
- 답변의 그림을 대시보드에 바로 추가하는 동선은 다음이다. 명세가 대시보드 위젯과 같은
  모양이라 붙이기는 어렵지 않다.
