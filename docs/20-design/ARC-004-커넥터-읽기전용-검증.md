# ARC-004 커넥터 읽기 전용 보장의 검증 방법

| | |
|---|---|
| 상태 | **확정** |
| 일자 | 2026-09-09 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `QUR.CON.001` (D1 조사, GH-42) |

## 1. 결정

`QUR.CON.001`(커넥터는 원천 도구의 데이터를 변경하지 않는다)의 검증 방법 `R`(공식검토)을
**상시 자동 검사 + 최소 권한 지침 + 시연 시 1회 감사 대조**의 세 겹으로 확정한다.

| 겹 | 내용 | 시점 |
|---|---|---|
| ① 정적 검사 | 어댑터 소스에 GET 외 HTTP 호출이 있으면 시험이 실패한다 | CI, 커밋마다 |
| ② 최소 권한 | 연결 자격증명은 읽기 권한만 부여를 지침으로 한다 (GitHub 은 read-only PAT, Redmine 은 일반 조회 계정의 API 키) | 연결 등록 시 |
| ③ 감사 대조 | 수집 시연 전후로 원천 도구의 변경 이력이 비어 있음을 확인한다. GitHub 은 저장소 이벤트, Redmine 은 이슈 이력을 본다 | 시연 1회 |

## 2. 근거

**사람 검토는 한 번이고 코드는 계속 바뀐다.** 검토 시점의 결론("GET 만 쓴다")은 다음 커밋이
무효화할 수 있다. 그래서 검토 결론을 시험(`tests/test_readonly_guard.py`)으로 굳혀 어댑터가
추가·수정될 때마다 자동으로 다시 검토되게 한다. 그래서 GitLab·Jira 어댑터가 생겨도 자동으로 걸린다.

**상시 감사 로그 대조는 두지 않는다.** 원천 도구별로 감사 API 가 제각각이고(GitHub 조직 감사
로그는 유료 플랜), 대조 절차 자체가 원천에 대한 추가 접근이다. ① 이 코드 수준에서 쓰기 자체를
차단하고 ② 가 권한 수준에서 이중으로 막으므로, 감사 대조는 발주기관 앞 시연에서 신뢰를 보이는
용도로 1회만 수행한다.

## 3. 한계

정적 검사는 어댑터 디렉토리만 본다. 어댑터 밖에서 원천 도구를 직접 부르는 코드가 생기면
잡지 못한다. 다만 그런 코드는 포트 우회이므로 `SWFR.CON.001` 구조 위반이고, 코드 리뷰가 잡는다.
