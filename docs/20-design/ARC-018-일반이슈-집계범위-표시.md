# ARC-018 일반 이슈의 집계 범위와 요구사항 상태 출처 표시

| | |
|---|---|
| 상태 | **확정** |
| 일자 | 2026-10-02 |
| 결정 | 유저인사이트(주) 수행 책임자 |
| 관련 | `SWFR.WEB.001` `SWFR.WEB.002` `QUR.WEB.002` · ARC-005 · ARC-006 · ARC-013 |

---

## 1. 문제

10-02 대조에서 GitHub 의 열린 이슈는 36건인데 이슈 화면에는 11건이 보였다.

- 원천 번호로 맞춰 보니 수집 누락은 없었다. 36건 = 요구사항 라벨 30건 + 그 밖 6건이다.
- 요구사항 라벨이 붙은 이슈는 `requirement` 로, 나머지는 `issue` 로 간다(ARC-005).
- 화면의 11은 `issue` 의 전체(열림 6 + 닫힘 5)였다.

어긋남의 원인은 세 가지다.

1. 지표·화면·AI 답변이 `issue` 만 세면서 이름은 "이슈" 였다. GitHub 이슈 수와 견주면 안 맞는다.
2. 이슈 화면 카드는 목록 첫 쪽(100건)을 받아 손에서 셌다. 100건이 넘으면 카드가 잘린다.
3. 요구사항의 IMPLEMENTED 는 GitHub 이슈가 닫히면 붙는데 화면에는 "구현" 으로 보였다. 원천 이슈가 닫혔다는 사실과 구현을 확인했다는 뜻이 섞인다.

## 2. 결정

### 2-1. 이름은 "일반 이슈", 설명은 "요구사항으로 분류된 항목 제외"

내부 분류(`issue` 와 `requirement`)와 지표 키·산식은 그대로 둔다. 바꾸는 것은 사람이 읽는 이름이다.

| 자리 | 바꾼 것 |
|---|---|
| 시맨틱 지표 | `issue_count` 등 7개의 label 과 basis(V45). 키·산식은 그대로 |
| 시맨틱 차원 | `issue_status` `issue_severity` 의 label(V45) |
| 이슈 화면 | 제목 "일반 이슈", 머리 설명, 카드 이름 |
| 진척 | `ProgressMeasure.label` "일반 이슈 해결률", note 에 범위 |
| 위젯 | 템플릿 예시 제목, 프리셋 제목 |
| AI 답변 | 현황 그림 제목, 목록 표 이름과 범위 줄 |
| 사업 목록 | "이슈" 열을 "요청·시정·리스크" 로. 실제로 그 세 건수를 보인다 |

**합산 지표는 만들지 않는다.** "GitHub 열린 이슈 36" 은 원천 기준 수이고 표준 지표가 아니다.
요구사항 30 과 일반 이슈 6 은 뜻이 다른 상태라 더하면 안 된다.

**저장된 위젯 제목은 덮어쓰지 않는다.** 사용자가 고친 제목일 수 있다. 위젯 카드의 부제는
지표 label 을 그 자리에서 읽으므로("열린 일반 이슈 수 · 프로젝트 1개") 범위는 거기 드러난다.

### 2-2. 이슈 화면 카드는 서버가 센다

`GET /api/projects/{id}/issues/summary`

| 칸 | 조건 |
|---|---|
| total | 사업의 `issue` 전부 |
| open | 상태 OPEN · IN_PROGRESS |
| closed | 상태 RESOLVED · CLOSED |
| heavyOpen | 열린 것 중 심각도 BLOCKER · CRITICAL · MAJOR |
| unassignedOpen | 열린 것 중 담당이 비었거나 공백 |

- 권한 검사는 목록과 같은 함수다.
- 목록은 쪽을 끝까지 넘겨 받는다. 표가 검색·정렬을 손에서 하기 때문이다.
- 목록 정렬 끝에 `id` 를 붙였다. 한 번에 승격된 행은 시각이 같아서, 없으면 쪽을 넘길 때 같은 행이 두 번 나오고 어떤 행은 빠진다(130건 시험에서 확인).

### 2-3. 요구사항 상태의 출처

- 응답에 `statusBasis` 를 더한다. GitHub 연결에서 온 요구사항이 IMPLEMENTED 일 때만 `SOURCE_ISSUE_CLOSED`, 그 밖에는 null 이다.
- 화면은 이 값이 있을 때만 "원천 이슈 닫힘" 과 "구현·검증 완료를 뜻하지 않음" 을 함께 보인다.
- 다른 도구, 문서, 수기에서 온 IMPLEMENTED 는 "구현" 그대로다. GitHub 닫힘으로 설명하지 않는다.
- AI 목록 표의 상태 열도 같은 규칙이다.
- 내부 상태 체계와 이행률 산식(VERIFIED · ACCEPTED 만 분자)은 바꾸지 않는다.

## 3. 하지 않은 것

- 상태별로 묶는 위젯(`requirement_status` 차원)에서 "구현" 칸은 출처를 나눠 보이지 않는다. 지금 데이터의 IMPLEMENTED 는 전부 GitHub 닫힘에서 왔다. 차원을 바꾸는 일은 상태 체계 논의와 같이 한다.
- 라우팅 프롬프트의 예문("이슈 목록", "열린 이슈")은 그대로다. 사용자가 그렇게 묻기 때문이다.
- 기존 저장 위젯 중 "요구사항 상태별 건수" 는 `issue_count` 를 쓴다. 제목과 지표가 어긋난 사용자 위젯이라 손대지 않고 알린다.
