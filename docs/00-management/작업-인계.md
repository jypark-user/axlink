## 1. 왜 옮겼는가 — 환경 제약

Cowork 클라우드 컨테이너에서 아래가 **차단**되어 백엔드 작업이 불가능하다.

| 대상 | 클라우드 | 로컬(VS Code) |
|---|---|---|
| `repo1.maven.org` (Gradle 의존성) | **차단 (000)** | 가능 |
| `services.gradle.org` (래퍼 배포판) | **차단 (000)** | 가능 |
| Docker Hub (pgvector · Redmine · Ollama 이미지) | **차단** | 가능 |
| `api.github.com` | **차단 (502)** | 가능 |
| 로컬 Ollama `localhost:11434` | 도달 불가 | 가능 |
| `registry.npmjs.org` | 가능 | 가능 |

**그래서 프런트엔드까지는 클라우드에서 검증했고, 백엔드·인프라는 손대지 못했다.**

## 2. 지금까지 확인된 것

### ✅ 프런트엔드 — 빌드 통과 (클라우드에서 실증)

```
npm ci        → 516 packages, 0 vulnerabilities, 10s
npm run build → tsc -b 통과 + vite build 통과, 8.44s
```

산출물 34개 청크. 경고는 하나 — `index-*.js` 708 kB로 500 kB 권고치 초과.
**기능 문제는 아니다.** 코드 스플리팅은 M3 화면 작업 때 같이 본다.

> 검증 환경은 Linux + Node 22.22.2 다. Windows에서 재현 시 줄바꿈·경로
> 문제가 날 수 있으나 `.gitattributes`로 줄바꿈은 고정해두었다.

### ❌ 백엔드 — 미검증

`./gradlew build` 를 한 번도 돌리지 못했다. **이것이 첫 번째 할 일이다.**

### ❌ 인프라 — 미검증

`infra/docker-compose.yml` 기동, Flyway V1~V19 적용, pgvector 확장 설치 모두 미확인.

## 3. 첫 작업 — GitHub 이슈 「E 파일럿 인수 — 빌드·기동 확인」 (M1)

```bash
gh issue list --milestone "M1 범위·평가기준 확정"
```

체크리스트가 이슈 본문에 있다.

- [ ] backend `./gradlew build` 통과
- [ ] frontend `npm ci && npm run build` 통과 ← **이미 확인됨. 로컬 재현만**
- [ ] Flyway V1~V19 적용 확인 (pgvector 포함)
- [ ] 로컬 Ollama 없이 `fake` 어댑터로 기동 확인

**막히면 우회하지 말고 막힌 지점을 그대로 보고한다.** 파일럿은 수직 슬라이스만
구현된 상태(`docs/90-pilot/HANDOFF.md`)라 안 도는 게 있는 게 정상이다.
무엇이 안 도는지가 곧 다음 이슈의 재료다.

### 주의 — 파일럿의 알려진 충돌

`backend/src/main/resources/application.yml` 의 `chat: ${OLLAMA_MODEL_CHAT:qwen3.5:cloud}`
가 `QUR.RAG.001`(외부 클라우드 LLM 비의존)을 정면으로 위반한다. **파일럿 대조표에서
유일한 「충돌」 판정이다.** 지금 고치지 않는다 — GPU 확보 후 환경변수 교체로 해소한다
(`LlmPort` 구조라 코드 수정 불필요). 기동 검증은 `fake` 어댑터로 한다.

## 6. 작업 시 반드시 지킬 것

전문은 `CLAUDE.md`. 자주 어기게 되는 것만 추린다.

1. **`main` 직접 push 금지.** 브랜치 → PR → 사람이 병합.
2. **커밋 메시지에 대괄호 추적 ID 필수.** 해당 없으면 `[chore]`.
   `scripts/build_traceability.py --check` 가 CI에서 이걸 검사한다.
3. **이슈 참조는 `GH-` / `RM-` 접두.** 맨 `#17` 금지 —
   Redmine이 커밋의 `refs #123`을 자기 이슈로 자동 해석해 엉뚱한 데 연결된다.
4. **JPA 금지.** JdbcClient만. 스키마 변경은 **새 `V##__` Flyway 파일**로만
   (기존 마이그레이션 수정 금지).
5. **LLM은 수치를 생성하지 않는다.** 모든 수치는 시맨틱 레이어의 결정론적 집계.
6. **프론트에 목업 데이터 파일 금지. localStorage 금지.** 대시보드 상태의 단일 원천은 서버 DB.
7. **데이터 없는 메뉴는 만들지 않는다.** 화면보다 테이블과 수집 경로가 먼저다.

### 왜 이렇게 빡빡한가

**이 저장소 자체가 AX Link의 1번 샘플 프로젝트다.** 우리가 남기는 커밋·이슈·PR·문서를
우리 커넥터가 수집해서 추적표와 진척률을 자동 생성하고, 그걸 발주기관 앞에서 시연한다.
**규약을 어긴 커밋은 그 자체로 데이터 결함이고, 나중에 소급 수정이 안 된다.**
