# 현황 보기

사업의 진행 상황을 보는 화면들을 적는다. 왼쪽 메뉴의 현황 아래에 있는 진행 상황, 일정(WBS), 스냅샷, 일반 이슈, 요구사항이다.

| 항목 | 내용 |
|---|---|
| 화면 | 사업을 고른 뒤 왼쪽 메뉴의 현황 |
| 하는 사람 | 보기는 모두. 고치는 일은 발주기관 |
| 먼저 할 것 | 도구가 연결되고 첫 수집이 끝나야 숫자가 나온다. [도구 연동](도구-연동-가이드.md) |
| 기준 | 2026-11-16 |

이 화면들의 숫자는 수집한 데이터를 센 값이다. 메뉴로 들어가서 본 숫자와 AI 질의로 물어서 받은 숫자는 같은 집계에서 나온다. 둘이 다르면 오류이니 알려 주기 바란다.

## 진행 상황 {#dashboard}

사업의 주요 지표를 위젯으로 모아 보는 화면이다. 화면 제목은 대시보드다.

머리줄에 처리하지 않은 확인 요청이 있으면 "미처리 확인 요청 N건"이 보이고, 누르면 확인 요청 화면으로 간다.

<!-- 대상: 발주기관 -->
### 위젯 구성 바꾸기 {#dashboard-edit}

1. [편집 모드]를 누른다.
2. 위젯이 하나도 없으면 [기본 구성 놓기]를 누른다. 다른 구성을 쓰려면 머리줄의 [추천 구성]에서 하나를 고르고 [바꾸기]를 누른다. 추천 구성은 기본 구성, 전체 인포템플릿, 전체 진행 현황, 이슈와 위험 중심, 산출물과 요구사항 중심 다섯 가지다.
3. 위젯을 더하려면 오른쪽 판에서 종류(수치, 추이, 분포, 구성, 목록)를 고른다. [위젯 추가] 창에서 제목과 보고 싶은 내용을 적고 [생성]을 누른 뒤 [배치]를 누른다.
4. 위젯을 끌어서 옮기거나 모서리를 끌어 크기를 바꾼다.
5. 아래 [저장]을 누른다.

주의할 점이 있다.

- 추천 구성으로 바꾸면 지금 있는 위젯이 모두 지워진다.
- 위젯을 지우면 [저장]과 상관없이 바로 지워지고 되돌릴 수 없다.
- [초기화]를 누르고 확인하면 지금 위젯을 지우고 기본 구성으로 되돌린다.
- [전체 삭제]를 누르고 확인하면 위젯이 모두 지워진다.
- 기본 구성은 WBS 진척률·산출물 승인률·요구사항 이행률과 그 일별 추이, 진행 중인 WBS 작업, 담당자별 열린 이슈, 최근 2주 커밋·PR, 요구사항 단계, 열린 리스크, 일정·품질 카드로 이뤄진다. 일별 추이는 매일 찍는 스냅샷에서 오므로 스냅샷을 찍기 시작한 날부터 선이 그려진다.
- 위젯의 [수정]을 누르면 그 위젯을 왜 두었고 값이 어디서 오는지가 「만든 근거」에 보인다.
- 화면 구성은 서버에 저장된다. 다른 컴퓨터에서 열어도 같은 구성이 보인다.

## 일정(WBS) {#schedule}

용역사가 낸 WBS 를 기준으로 작업별 계획과 실적을 보는 화면이다.

1. 맨 위 「수치의 원천」에서 이 화면의 수치를 어느 파일에서 읽었는지 본다. 저장소와 파일 경로, 읽은 판(커밋), 반영 시각, 마지막 동기화 시각이 나온다. 파일 이름을 누르면 원본이 열린다.
2. 그 아래 카드에서 보고 진척률과 완료 확인율을 본다.
3. 아래 탭에서 간트, 칸반, 캘린더, WBS 가운데 보기 방식을 고른다. 고른 보기는 다음에 열 때도 그대로다. WBS 탭 표의 「완료 확인」 칸에서 작업마다 발주기관의 작업 완료 확인 상태를 본다.
4. 탭 오른쪽에 「격차 경고 n건」(격차 경고가 없으면 「확인할 점 n건」) 버튼이 있으면 눌러 경고 목록을 본다. 격차 경고는 WBS 에 실적 80% 이상으로 적었는데 산출물이 아직 없거나 연결 이슈가 열려 있는 작업이다. 해당 작업 줄에도 「격차 경고」 배지가 붙는다.

이 화면의 수치는 화면에서 고치지 않는다. 「수치의 원천」에 적힌 파일이 바뀌어 다시 수집돼야 바뀐다. 같은 이름의 다른 위치 파일은 읽지 않는다.

두 진척 값은 뜻이 다르다.

| 값 | 뜻 |
|---|---|
| 보고 진척률 | 용역사가 WBS 에 적은 실적을 가중치로 합친 값이다. 용역사의 보고다 |
| 완료 확인율 | 발주기관이 작업 완료를 확인한 작업의 가중치 합이다 |

파일 대조는 저장소에 그 산출물 파일이 있는지 본 결과다. 정식 제출과 같지 않다.

WBS 가 없으면 "진척률 산정의 핵심 입력이 빠져 있습니다"가 나온다. Redmine 이슈에 시작일과 종료일이 있으면 그것으로 일정을 대신 보여 준다. 이때는 가중치가 없으므로 추정치다.

WBS 가 없는 사업의 진척률은 **이슈 기반 추정 진척률**이다. 일반 이슈(리스크·결함 제외)마다 도구에 적힌 진척도를 같은 비중으로 평균한다. 진척도가 비어 있는 이슈는 0 으로 세고, 산출 근거에 「진척도가 없는 n건은 0으로 셌습니다」라고 적는다. 진척도가 적힌 이슈가 하나도 없으면(GitHub 이슈만 있는 경우 등) 진척률은 산출 불가로 나온다. 해결된 이슈의 비율(일반 이슈 해결률)은 진척률이 아니라 따로 보는 값이다. 사업 목록의 진척률 칸에는 「이슈 기반 추정」이 붙는다.

작업 일정 아래 계획서 인식 결과에서 WBS 파일을 어떻게 읽었는지 본다. 말단 작업 수, 묶음 수, 가중치 합, 산출물이 지정되지 않은 작업 수, 머리글 행, 항목별로 읽은 머리글과 열, 경고가 나온다. 가중치 합이 1.00 이 아니면 합으로 나눠 맞췄다고 표시한다. 이 화면에서 열을 다시 지정하거나 값을 고치는 기능은 없다. 잘못 읽혔으면 원본 파일을 고친다.

새로 수집한 WBS 파일을 읽지 못하면 계획서 인식 결과가 작업 일정 위로 올라와 「읽지 못했습니다」와 사유가 나온다. 직전에 읽은 판이 있으면 그 작업을 이전 기준선으로 계속 보여 준다. 읽은 작업이 없으면 진척률을 내지 않는다. 0% 로 보이지 않는다.

<!-- 대상: 발주기관 -->
작업 완료를 확인하는 일은 이 화면이 아니라 확인 요청에서 한다. 대상 종류를 WBS 항목으로, 요청 목적을 작업 완료 확인 요청으로 골라 요청한다. [확인 요청](확인-요청.md#completion)
<!-- /대상 -->

<!-- 대상: 용역사 -->
WBS 파일은 저장소에 커밋하거나 산출물로 올린다. 실적은 「수치의 원천」에 적힌 그 파일의 실적 열을 고쳐 다시 커밋하면 다음 수집 때 반영된다. [도구 연동](도구-연동-가이드.md)

## 스냅샷 {#snapshots}

진척률과 주요 지표를 날짜별로 남긴 기록이다. 추이 그래프와 보고서의 숫자가 여기서 나온다.

1. 머리줄에서 마지막 기록 시각, 다음 기록 시각, 기록 빈도를 본다.
2. 지표별 진척률 추이 그래프에서 계획, 진척률(WBS), 진척률(산출물), 진척률(요구사항 이행) 네 선을 본다. 모두 % 다. 기록이 하루치뿐이면 아직 선이 되지 않는다.
3. 아래 표에서 날짜마다 같은 네 지표와 편차(WBS − 계획), 지연 작업, 이슈 해결, 리스크 종료를 본다. 산출물·요구사항 칸 밑에는 그날 센 건수(승인 산출물/WBS 지정 산출물, 검증·인수 요구사항/이행률 대상 요구사항)가 붙는다.

네 지표는 진행 상황의 기본 구성 카드와 같은 산식이다. 같은 날이면 두 화면의 수치가 같다.

스냅샷은 정한 시각에 하루 한 번 자동으로 남는다. 수집(동기화)과는 다른 일이다.

표의 산정 칸에는 그날 진척률을 어떤 산식으로 냈는지가 나온다. WBS 가 없는 사업은 2026-11-16 부터 이슈 기반 추정 진척률로 바뀌었고, 그 전 기록은 「일반 이슈 해결률(옛 L3 산식)」로 나온다. 예전 기록은 고치지 않는다. WBS 가 없는 사업은 산정 칸에 그날 대표 진척률이 따로 나오고, 산식이 전날과 다르면 「산식 바뀜」이 붙는다.

<!-- 대상: 발주기관 -->
지금 상태로 남기려면 [지금 찍기]를 누른다. 같은 날 다시 찍으면 그날 기록을 덮어쓴다. 기록 시각을 바꾸는 방법은 [사업 설정](사업-설정.md#collection-settings)에 있다.
<!-- /대상 -->

## 일반 이슈 {#issues}

GitHub 와 Redmine 에서 수집한 이슈 가운데 요구사항, 리스크, 결함이 아닌 것을 모아 본다.

1. 위쪽 연결 선택에서 전체 연결이나 특정 연결을 고른다.
2. 카드에서 열린 일반 이슈, 심각하거나 높은 것, 담당 없는 것, 해결되거나 닫힌 것의 수를 본다.
3. 이슈 제목으로 찾을 수 있다.
4. 줄을 누르면 도구, 연결, 원문 링크, 심각도, 마일스톤, 담당이 열린다.

도구에 심각도 값이 없으면 "미지정"으로 나온다. 이 화면은 보기만 한다. 이슈는 원래 도구에서 고친다.

## 요구사항 {#requirements}

확정된 요구사항 목록과 각 요구사항이 설계, 구현, 시험과 어떻게 이어졌는지 보는 화면이다.

1. 위쪽 카드(전체 요구사항, 검증 완료, 검증 미완료)나 상태별 건수를 누르면 그 조건으로 목록이 걸러진다. [해제]로 푼다.
2. 코드나 요구사항 이름으로 찾을 수 있다.
3. 코드를 누르면 상세가 열린다.

목록의 칸은 다음과 같다.

| 칸 | 뜻 |
|---|---|
| 상태 | 정의, 구현, 검증, 인수 같은 지금 상태 |
| 연관 이슈·일감 | 이 요구사항 ID 를 적은 이슈·일감 중 닫힌(해결·종료) 건수와 전체 건수, 진행 막대. 진행·열림 건수가 아래에 붙는다. 하나도 없으면 「등록된 이슈 없음」 |
| 관련 설계 문서 | 이 요구사항 ID 를 적은 설계 문서. 설계가 끝났다는 뜻은 아니다 |
| 관련 커밋·PR | 이 요구사항 ID 를 적은 커밋과 PR |
| 시험 연결 | 이 요구사항과 이어진 시험. 통과했다는 뜻은 아니다 |

연결이 있다고 해서 완료나 통과를 뜻하지는 않는다. 원천이 사라진 연결은 붉게 보인다.

「연관 이슈·일감」은 용역사가 그 요구사항으로 일을 얼마나 등록했고 얼마나 닫았는지 보는 칸이다. 용역사가 이슈·일감의 제목이나 본문에 요구사항 ID 를 적으면 다음 수집 때 이어진다. 요구사항 ID 를 누르면 열리는 상세에서 이어진 이슈·일감 하나하나와 상태를 본다. 이 칸은 요구사항 이행률(검증·인수 건수)과 따로다.

상태는 기본으로 수집한 원천대로 움직인다. 예를 들어 예전에 이슈로 만든 요구사항은 그 이슈가 닫히면 구현이 된다. 명세서로 등록한 요구사항은 지정하기 전까지 정의에 머문다. 이때 상태 칸에는 "출처 이슈 닫힘"이라고 나온다. 구현을 누가 확인했다는 뜻은 아니다.

<!-- 대상: 발주기관 -->
### 상태 지정 {#requirement-decision}

검증과 인수는 수집으로 정해지지 않는다. 발주기관이 연관 이슈·일감과 산출물을 보고 직접 지정한다. 요구사항 이행률(검증과 인수 건수를 전체로 나눈 값)은 지정해야 올라간다.

1. 요구사항 줄의 [상태 지정]을 누른다. 이미 지정했으면 [상태 변경]으로 나온다.
2. 지정할 상태를 고른다. 사유는 적어도 되고 비워도 된다. 적으면 함께 남는다.
3. [지정]을 누른다.

지정한 사람과 시각(사유를 적었으면 사유도)은 변경 이력에 남고 용역사에게 알림이 간다. 다시 수집해도 지정한 상태는 바뀌지 않는다. 지정을 거두려면 같은 창에서 [지정 해제]를 누른다. 해제한 뒤로는 다시 원천대로 움직인다.
<!-- /대상 -->

<!-- 대상: 용역사 -->
요구사항의 상태 지정은 발주기관이 한다. 용역사는 지정 결과와 사유를 볼 수 있다. 지정이 바뀌면 알림이 온다.
