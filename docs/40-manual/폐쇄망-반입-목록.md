# 폐쇄망 반입 목록

외부 인터넷이 없는 서버에 AX Link 를 설치하려면 무엇을 들고 들어가야 하는지 적은 목록이다.
(근거였던 `SER.SEC.002` 는 IM-001 v0.4.2 에서 폐기했고, 설치 참고용으로 남긴다.) 설치 절차 자체는 [배포·운영 절차](배포-운영-절차.md)를 따르고, 이 문서는
그 절차가 바깥에서 받아 오는 것을 전부 미리 챙기는 데 쓴다.

기준: `infra/docker-compose.prod.yml` · `infra/prod.env.example` · 2026-11-03 개발 PC 실측.

## 1. 어디서 인터넷을 쓰는가

| 때 | 받는 것 | 폐쇄망에서는 |
|---|---|---|
| 이미지 빌드 | 베이스 이미지(python·node·nginx·flyway), pip·npm 패키지, pgjdbc | **하지 않는다.** 이미지는 바깥에서 만들어 들고 들어간다. 베이스·패키지는 만들어진 이미지 안에 들어 있다 |
| 스택 기동 | 레지스트리에서 이미지 pull | `docker load` 로 넣은 이미지를 쓴다. `AXLINK_IMAGE_PREFIX` 는 들여온 이미지 이름과 같게 둔다 |
| 모델 준비 | `ollama pull`(모델 파일), 클라우드 모델 로그인 | 모델은 볼륨째 들고 들어간다. **클라우드 모델은 쓸 수 없다.** 같은 자리에 온프레미스 모델을 둔다 |
| 운영 중 | 원천 도구(GitHub·Redmine) API, Ollama | 원천 도구가 기관 내부망에 있으면 내부망으로 연결한다. 인터넷에 있으면(GitHub.com 등) 수집 서버에서 그 도구 주소로 가는 연결만 연다(보안대책 운영 수칙 7). Ollama 는 같은 스택이나 내부 서버다. 그 밖의 외부 호출은 없다(IM-003 10절) |

앱이 바깥으로 내는 HTTP 는 두 커넥터(GitHub·Redmine)와 모델 서버 호출뿐이다(`test_readonly_guard`,
`test_review_no_source_write`). 스케줄러는 API 안에서 돌아 cron 같은 반입 요소가 없다.

## 2. 반입 목록

### 2-1. 컨테이너 이미지

`docker save` 로 tar 를 만들고 sha256 과 함께 옮긴다. 크기는 개발 PC 의 `docker images` 값(압축 전)이다.

| 이미지 | 태그·버전 | 크기 | 쓰는 곳 | 비고 |
|---|---|---|---|---|
| `axlink-api` | 배포 버전(`AXLINK_VERSION`) | 약 420MB | 화면 API·수집·스케줄러 | CI 가 만든 것. 라벨 `org.opencontainers.image.revision` 이 커밋이다 |
| `axlink-web` | 같은 버전 | 약 100MB | 화면(nginx) | |
| `axlink-migrate` | 같은 버전 | 약 800MB | 스키마 마이그레이션 | Flyway 10 + pgjdbc + `db/migration` |
| `pgvector/pgvector` | `pg16` | 약 620MB | PostgreSQL + pgvector | 다른 버전으로 바꾸지 않는다. 덤프 호환 때문이다 |
| `ollama/ollama` | `0.33.1`(`AXLINK_OLLAMA_TAG`) | 약 8.5GB | 모델 서버 | 다른 서버의 Ollama 를 쓰면 빼고 `AXLINK_BUNDLED_OLLAMA=0` |

세 앱 이미지는 반드시 **같은 버전·같은 커밋**이어야 한다. 들여온 뒤 라벨로 맞춰 본다
(배포·운영 절차 2절).

### 2-2. 모델 파일

Ollama 볼륨(`/root/.ollama`)을 통째로 옮긴다. 바깥 PC 에서 같은 Ollama 버전으로 `pull` 한 뒤 그
볼륨을 tar 로 뜬다. 모델은 `ollama list` 에 보여야 앱이 고를 수 있다.

| 역할 | 모델 | 크기 | 비고 |
|---|---|---|---|
| 임베딩 | `bge-m3` | 약 1.2GB | **필수.** 1024차원. 다른 임베딩 모델로 바꾸면 기존 색인을 전부 다시 만들어야 하고 앱이 섞임을 막는다(ARC-022) |
| 생성 | 온프레미스 모델 하나 | 모델에 따라 | **미결(4절).** 개발 PC 는 클라우드 모델(`gemma4:31b-cloud`)을 쓰고 있어 폐쇄망에 그대로 못 간다 |

개발 PC 에서 실측한 온프레미스 후보: `qwen3:8b`(약 5.2GB) · `qwen3:4b`(약 2.5GB, CPU 추론 실측
기록은 ARC-010 8절). GPU 서버 사양이 정해지면 그 사양에 맞는 모델을 고르고 이 표를 채운다.

### 2-3. 파일

| 파일 | 어디서 | 비고 |
|---|---|---|
| `infra/docker-compose.prod.yml` | 저장소, 배포 버전과 같은 커밋 | 스택 정의 |
| `infra/prod.env.example` → 실제 값 파일 | 저장소 예제를 바탕으로 작성 | 비밀값 셋(`AXLINK_DB_PASSWORD`·`AXLINK_JWT_SECRET`·`AXLINK_SECRET_KEY`)은 바깥에서 만들어 넣고 **반입 매체에 평문으로 두지 않는다** |
| `docs/40-manual/배포-운영-절차.md` · 이 문서 · `사용-설명서.md` | 저장소 | 설치하는 사람이 본다 |
| 데이터 덤프 (선택) | `pg_dump -Fc` | 개발 환경 데이터를 가져갈 때만. 그때는 `AXLINK_SECRET_KEY` 를 **원래 키 그대로** 쓴다. 새 키로는 저장된 연결 토큰을 풀 수 없다 |
| 업로드 원본 (선택) | `documents` 볼륨 tar | 덤프와 짝으로 옮긴다 |

### 2-4. 들고 들어가지 않는 것

- 소스 코드, Node·Python 런타임, pip·npm 패키지: 전부 이미지 안에 있다.
- Redmine 이미지: 선택 프로필이고 발주기관 환경에 원천 도구가 따로 있다는 전제다. 시연용으로
  Redmine 을 안에 세울 때만 `redmine:6`·`postgres:16` 을 더한다.
- 재순위(reranker) 모델: 쓰지 않는다(ARC-010 9절).

## 3. 옮기는 절차

바깥(인터넷 되는 PC)에서:

```bash
# 1) 이미지. 다이제스트로 받아 저장한다
docker pull ghcr.io/jypark-user/axlink-api:<버전> && docker pull ghcr.io/jypark-user/axlink-web:<버전> \
  && docker pull ghcr.io/jypark-user/axlink-migrate:<버전>
docker pull pgvector/pgvector:pg16 && docker pull ollama/ollama:0.33.1
docker save -o axlink-images-<버전>.tar ghcr.io/jypark-user/axlink-api:<버전> \
  ghcr.io/jypark-user/axlink-web:<버전> ghcr.io/jypark-user/axlink-migrate:<버전> \
  pgvector/pgvector:pg16 ollama/ollama:0.33.1

# 2) 모델. 빈 볼륨에 받아서 그대로 뜬다
docker run -d --name ollama-export -v ollama-export:/root/.ollama ollama/ollama:0.33.1
docker exec ollama-export ollama pull bge-m3
docker exec ollama-export ollama pull <온프레미스 생성 모델>
docker run --rm -v ollama-export:/src -v "$PWD":/out alpine tar czf /out/ollama-models.tar.gz -C /src .

# 3) 검증값
sha256sum axlink-images-<버전>.tar ollama-models.tar.gz > SHA256SUMS
```

안(폐쇄망 서버)에서:

```bash
sha256sum -c SHA256SUMS
docker load -i axlink-images-<버전>.tar
docker volume create axlink_ollama
docker run --rm -v axlink_ollama:/dst -v "$PWD":/in alpine tar xzf /in/ollama-models.tar.gz -C /dst
# 그 뒤는 배포·운영 절차 3절(스택 변수·기동)과 4절(계정·모델 선택)
docker compose exec ollama ollama list      # bge-m3 와 생성 모델이 보여야 한다
```

볼륨 이름은 Compose 프로젝트 이름에 따라 `<프로젝트>_ollama` 가 된다. 들여올 때 그 이름으로
만들거나 스택을 먼저 띄워 생긴 볼륨에 풀어 넣는다.

## 4. 정하지 않은 것·아직 안 한 것

| 항목 | 상태 |
|---|---|
| 온프레미스 생성 모델 | **미결.** GPU 서버 사양(인프라-배치방안 5절)이 먼저다. 정해지면 2-2 표와 `AXLINK_LLM_MODEL` 기본값을 바꾼다 |
| 배포 서버 CPU 구조 | amd64 기준. 아니면 이미지를 그 구조로 다시 만들어 들고 간다 |
| 오프라인 설치 리허설 | **아직 하지 않았다.** 외부를 끊은 서버에서 이 목록만으로 기동되는지 확인한 기록이 없다. 리허설 결과는 IM-005 TST-040 에 적는다 |
| 반입 매체·보안 검토 절차 | 발주기관 규정에 따른다. 비밀값은 매체에 두지 않는다(2-3) |
