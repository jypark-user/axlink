# 사용 설명서

AX Link 를 쓰는 방법을 기능별로 적은 설명서다. 왼쪽 목록에서 문서를 고른다. 로그인한 계정의 역할에 맞는 문서와 단락만 보인다.

앱의 사용 설명서 화면은 이 파일을 그대로 보여 준다. 화면 위의 [이 문서 PDF], [전체 PDF] 단추로 PDF 를 만들 수 있다. 인쇄 화면이 열리면 그림이 다 불러와진 뒤 [PDF로 저장]을 누르고, 인쇄 창의 대상을 "PDF로 저장"으로 고른다.

## 처음 쓰는 순서 {#getting-started}

<!-- 대상: 발주기관 -->
발주기관 담당자는 다음 순서로 시작한다.

1. 플랫폼 관리자에게 받은 아이디와 임시 비밀번호로 로그인하고 비밀번호를 바꾼다. [로그인과 계정](로그인과-계정.md)
2. 사업을 등록하고 용역사를 초대한다. [사업 설정](사업-설정.md)
3. 용역사가 도구를 연결하고 요구사항 명세서를 제출하면 검토해서 확정한다. [요구사항 등록](요구사항-등록.md)
4. 대시보드과 일정을 보고, 확인할 것이 있으면 확인 요청을 보낸다. [현황 보기](현황-보기.md), [확인 요청](확인-요청.md)
5. 궁금한 것은 AI 질의로 물어본다. [AI 질의](AI-질의.md)
<!-- /대상 -->

<!-- 대상: 용역사 -->
용역사 담당자는 다음 순서로 시작한다.

1. 발주기관에게 받은 초대 링크로 계정을 만든다. [로그인과 계정](로그인과-계정.md)
2. 사업의 GitHub 저장소나 Redmine 을 연결하고 첫 수집을 돌린다. [도구 연동](도구-연동-가이드.md)
3. 요구사항 명세서를 올려 등록하고 제출한다. [요구사항 등록](요구사항-등록.md)
4. 커밋과 이슈에 요구사항 ID 를 적는다. 적힌 ID 로 요구사항과 이어진다. [도구 연동의 저장소 규약](도구-연동-가이드.md#conventions)
5. 발주기관의 확인 요청이 오면 조치하고 보고한다. [확인 요청](확인-요청.md)
<!-- /대상 -->

<!-- 대상: 관리자 -->
플랫폼 관리자는 발주기관과 그 담당자 계정을 만드는 일부터 한다. [플랫폼 관리](플랫폼-관리.md)

## 역할 {#roles}

AX Link 계정에는 세 가지 역할이 있다. 볼 수 있는 사업과 할 수 있는 일이 역할에 따라 다르다.

| 역할 | 볼 수 있는 사업 | 주로 하는 일 |
|---|---|---|
| 발주기관 | 자기 기관의 사업 | 사업 등록, 요구사항 확정, 확인 요청, 산출물 승인 |
| 용역사 | 초대받아 할당된 사업 | 도구 연결, 명세서 제출, 산출물 제출, 조치 보고 |
| 플랫폼 관리자 | 모든 사업 | 기관과 계정 발급, 시스템 설정 |

용역사도 대시보드, 일정, 요구사항 같은 현황 화면을 볼 수 있다. 발주기관이 무엇을 보고 요청하는지 같은 화면으로 알 수 있게 하려는 것이다. 다만 현황 화면에서 고치는 일은 발주기관이 한다.

## 공통 원칙 {#principles}

- 도구는 읽기만 한다. AX Link 는 GitHub 와 Redmine 에 아무것도 쓰지 않는다.
- 숫자는 집계에서만 나온다. 화면과 AI 답변의 숫자는 수집한 데이터를 센 값이다. AI 가 숫자를 만들지 않는다.
- 적힌 ID 로만 잇는다. 요구사항과 커밋, 이슈는 요구사항 ID 가 적혀 있을 때만 이어진다.
- ID 는 적을 때 같이 적는다. 커밋이나 이슈에 ID 를 빠뜨리면 나중에 이을 방법이 없다.
