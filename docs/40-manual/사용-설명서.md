# 사용 설명서

AX Link 의 기능별 설명서다. 기능마다 같은 틀로 적는다: 화면과 하는 사람, 흐름, 정해진 동작(규칙), 받는 형식과 받지 않는 형식, 오류와 해결, 제한, 관련 문서.
화면의 안내 문구와 이 문서가 다르면 문서 쪽을 고친다. 두 곳은 같은 파일에서 나온다.

## 처음 쓰는 순서 {#getting-started}

1. **도구를 붙인다.** 용역사의 GitHub·Redmine 을 사업에 연결하고 첫 수집을 돌린다. → [도구 연동](도구-연동-가이드.md)
2. **요구사항을 등록한다.** 요구사항 명세서를 올려 목록을 만들고 발주기관이 확정한다. → [요구사항 등록](요구사항-등록.md)
3. **커밋·이슈에 요구사항 코드를 적는다.** 적힌 코드로 요구사항과 이어진다. → [도구 연동 › 저장소 규약](도구-연동-가이드.md#conventions)

## 기능 {#features}

| 기능 | 무엇을 하나 | 하는 사람 |
|---|---|---|
| [도구 연동](도구-연동-가이드.md) | GitHub·Redmine 연결, 수집, 권한, 수집한 것이 어디로 가는지 | 용역사 · 발주기관 |
| [요구사항 등록](요구사항-등록.md) | 명세서로 요구사항 목록을 만들고 기준선으로 확정 | 용역사(등록) · 발주기관(확정) |

다른 기능(진행 상황, 일정, 산출물, 확인 요청, 질의)의 설명서는 이어서 쓴다.

## 공통 원칙 {#principles}

- **원천 도구는 읽기만 한다.** AX Link 는 GitHub·Redmine 에 아무것도 쓰지 않는다.
- **숫자는 집계에서만 나온다.** 화면과 AI 답변의 숫자는 수집한 데이터를 센 값이다. AI 가 숫자를 만들지 않는다.
- **근거 없는 연결은 만들지 않는다.** 요구사항과 커밋·이슈는 글자로 적힌 코드가 있을 때만 잇는다. 짐작으로 잇지 않는다.
- **추적은 적는 순간에만 만들어진다.** 커밋·이슈에 코드를 빠뜨리면 나중에 소급해 잇지 못한다.
